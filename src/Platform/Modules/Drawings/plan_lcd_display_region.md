# 架构层方案：基于「显示区域几何检测」的 LCD 屏显语义分类

> 目标：从根本上解决 `8888` 类 LCD 示例数字被误标红的问题，**且不损伤**序列号 / 日期码 / 电话号码等正常打印文本的识别准确率。
> 原则（用户硬约束）：立足架构底层系统性解决，而非按字符串打补丁。

---

## 一、影响验证结论（已用真实数据库实证）

扫描 `data/app.db` 全部 99 个块的 `drawing_blocks.RawText`，统计"纯数字文本行"：

- **当前未被灰化的纯数字真实文本共 73 条**（本应正常红/绿比对），构成：
  - 长度 2：45 条（`38`/`12`/`35`/`60`/`22`/`20`… 真实型号后缀/小编码）
  - 长度 4：**仅 1 条 `8888`**（did112-b1，正是想豁免的 LCD 示例）
  - 长度 6：23 条（`200512` 日期/批次码，**必须识别**）
  - 长度 7：4 条（`1250001`/`1178353` 批次码，**必须识别**）

各候选"纯数字 LCD 豁免"规则的误伤量：

| 豁免规则 | 误伤真实文本 |
|---|---|
| 纯数字 长度1-4 | 46/73（抓到 8888，但 45 条真实小编码全被灰化） |
| 纯数字 长度1-6 | 69/73（连 `200512` 日期码也误灰） |
| 纯数字 长度1-8 | 73/73（全部误灰） |
| 全同数字(8888/0000) | 8/73（仍误伤 `88`/`22`/`00` 等真实编码） |

电话/序列号同样脆弱：`服务热线4008601111` 去符号变纯 10 位数字、`B280001` 去符号变 `280001`——OCR 一旦漏掉"服务热线"前缀或横线/字母，内容规则即误判为 LCD 示例而灰化。

**结论：内容（文本是什么）无法区分"屏显示例"与"打印打标"。任何按文本内容的豁免规则都会系统性误伤正常文本。这正是架构在 2026-07-28 主动删除"纯数字=LCD"规则的原因。**

---

## 二、根因

能区分二者的不是**内容**，而是**物理位置**：
- LCD 示例数字（`8888`）画在产品的 **LCD/LED 屏幕区域（带边框的显示矩形）** 内，实物屏幕关机时为空白，本就不是"缺标"。
- 日期码 / 序列号 / 电话号码 / 型号码是**打印/雕刻在标签或外壳上**，物理上位于屏幕区域之外，缺失即真实缺陷。

---

## 三、架构方案：物理文本区域分类器（新增管线阶段）

新增一个**内容无关**的分类阶段，依据文本在参考图中的**几何位置**判定其物理语义：

### 1. 屏显区域检测 `_detect_display_regions(block_img)`
- 复用现有 `_dense_rects(gray, ...)`（diff_visualizer.py:1038，已能找密集矩形）的思路，检测"高填充、深色、带边框、屏幕典型长宽比"的矩形 = LCD/LED 面板。
- 返回块图坐标系下的显示区域 bbox 列表。

### 2. 物理类归属
- 每个块参考图文本行的 bbox 质心落在某显示区域内 → `class = display`（动态屏显内容）；
- 否则 → `class = printed`（永久打印打标）。

### 3. 灰/红门控（单点接入 `_compare_block` step4）
- 位置：在 line ~2223 `_is_cad_annotation(bt)` 判定之后、红绿匹配之前新增：
  ```python
  if _physical_class(bt_bbox, display_regions) == "display":
      res["gray_block"].append(bbox); res["cadOnly"].append(bt); continue
  ```
- `display` → 灰（非缺陷）；`printed` → 走现有红/绿/黄逻辑。

### 4. 双路径受益（无需重复改照片路径）
- `run()`（块匹配）与 `run_on_photo`（H5 照片直标）**共用 `_compare_block` 结果**。
- 单点分类即可让 `8888` 在块匹配与照片红框中同时变灰，消除上一轮红框偏移问题的"补丁感"，回归统一架构。

---

## 四、为何是架构级（而非补丁）

- **无**按字符串白名单、**无** `8888` 硬编码、**无**长度/小数启发式。
- 泛化到**任意** LCD 示例（`173` / `00:00` / `8888` / 全段显示），无需为新字符串加规则。
- 所有打印文本（日期码 `200512`、序列号 `B280001`、电话 `400-860-1111`）因物理位于屏外而**天然保留**红绿比对，准确率不受损。
- 屏显区域检测器是可复用原语，未来其它"动态内容"场景同样受益。

---

## 五、实施护栏（待你确认后落地）

1. **块参考图可用性**：`_compare_block` 需拿到块图路径做屏显检测。`run_on_photo` 已有 `blk_path`；`run()` 经 DB `FileRel` 取图。需确认/传入，零改动既有契约。
2. **检测鲁棒性**：
   - FN（漏检屏幕 → `8888` 仍红）与 FP（误检深色矩形 → 误灰打印标签）都需调参 + 样例回归。
   - 区域级（文本质心是否在屏内）而非整块级，避免同块内"屏+标签"混合时过度豁免。
3. **回归保障**：
   - 现有 `validate.py` 基线 `R=28 Y=20 G=588 Gray=664` 必须保持（仅 8888 由 red→gray 的有意变更，其余零负向）。
   - 新增定向断言：`8888`→gray；`200512`/`1250001`/服务热线/序列号→仍 red/green。

- 属 drawings 模块内维护升级，符合本对话范围。
