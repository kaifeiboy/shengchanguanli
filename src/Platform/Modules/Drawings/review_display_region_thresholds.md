# 屏显识别方案与阈值评审（已落地，待校准+开开关）

> 解决「8888」类 LCD 示例数字被误标红。架构级根因修复：**文本"内容"无法区分屏显示例与
> 印刷打标；能区分的是"物理外观"——LCD 是「浅色数字 + 深色底板」**。

---

## 一、已落地的机制（v19.40 候选）

`_detect_display_regions(img_path, ocr_lines)` —— **LCD 形态文本 + 深色面板校验**：

1. 遍历块图 OCR 文本行，筛出 **LCD 形态文本**：
   - 去符号后长度 ≥ `_DISP_MIN_LEN`(2)
   - 含中文 → 必拒（印刷标签）
   - 字母占比 ≤ `_DISP_ALPHA_RATIO_MAX`(0.15)（超则铭牌/品牌，拒绝认屏，保守保留潜在红）
   - 数字/符号(0-9 `:` `.` `-` `/` 空格)占比 ≥ `_DISP_LCD_SCORE_MIN`(0.80)
2. 物理校验：采样该文本 bbox 区域（外扩 4px）的**深色像素占比**；
   若 ≥ `_DISP_PANEL_DARK_FRAC`(0.45) → 确认坐在"深色底板"(LCD 面板) → 屏显文本，灰化跳过红框。
3. 返回 `(regions, display_text_keys)`；`display_text_keys` 供 `_compare_block` step4 按归一化键灰化。

接入点（仅 `diff_visualizer.py`）：
- `_compare_block(..., display_texts=None)`：step4 在 CAD 灰化后插入"屏显灰化"门控。
- `run()`：用实时块 OCR(block_lines) 计算 display_texts 传入。
- `run_on_photo()`：用真实块 OCR(`PR.ocr_photo_tiled(blk_path)`) 计算 display_texts 传入，
  并复用该 OCR 消除原 L2781 重复推理。

开关 `ENABLE_DISPLAY_REGION_GRAY = False`（默认关）：关时函数直接返回空 → 行为与今日逐字节一致（零回归）。

## 二、为什么这版比"几何候选框"更稳（实测发现）

首版用 `_dense_rects` 找"密集深色矩形"作屏候选，再要求屏内 OCR 文本。实测 did112-b1：
LCD 是浅色数字+深色底板，`_dense_rects` 只抓到 digit 段碎片（6 个碎框），可读数字 `8.888`
位于 x=325-388，**在所有候选框之外** → 位置判定彻底失效，8888 不触发。

改版直接对"LCD 形态文本"采样其 bbox 是否深色底板，绕过碎片问题：did112-b1 实测
`8.888` 区域 dark≈高 → 确认，键 `8888` 命中 → 8888 灰化。

## 三、阈值与 R1（误检）护栏

| 参数 | 值 | 作用 |
|---|---|---|
| `_DISP_LCD_SCORE_MIN` | 0.80 | 数字/符号主导才认 LCD 形态 |
| `_DISP_ALPHA_RATIO_MAX` | 0.15 | 字母占比高→铭牌/品牌，拒绝（保守） |
| `_DISP_REJECT_CJK` | True | 含中文必为印刷→永不灰（安全网，方向"宁多报不漏报"） |
| `_DISP_PANEL_DARK_FRAC` | 0.45 | bbox 深色像素占比≥此→确认 LCD 底板 |
| `_DISP_MIN_LEN` | 2 | 避免单数字误判 |

**R1 压制（实测已验证）**：白底印刷的数字（如 `200512`/序列号/电话）bbox 区域非深色
→ 不确认 → 不灰，正常红/绿比对。仅"数字坐在深色底板"才灰。

## 四、残留风险

| 风险 | 场景 | 严重度 | 应对 |
|---|---|---|---|
| 白底反白印刷的纯数字 | 深色底印数字（如反白型号）被当 LCD | 低 | 概率极低；即便发生→误灰（保守方向，不丢真实缺陷报红）；99 块扫描会暴露 |
| 字母屏显未自动灰 | 真 LCD 显示 COOL/HEAT | 无损 | 字母占比>15%→拒绝认屏→保留潜在红（安全默认，不损印刷文本） |
| 屏区域几何漏检 | — | 低 | 退化为现状（8888 仍红），绝不比现在差 |
| 缓存内存 | KB 级 | 极低 | 按 (path,mtime) 失效 |
