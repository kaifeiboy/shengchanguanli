## 〇、结论摘要（先给结论）

1. **你的判断属实**：当前系统在**不人工指定视图**时，无法识别"照片对应图纸哪一面"——自动视图推断 `InferViewFromBlind` 对真实照片返回空；一旦给定视图，对比能跑，但**真实照片上 OCR 读不到的声明 mark 会被判 Missing（红）**，产生批量假红警。

## 二、识别失效（无法识别照片对应的图纸部位）— 根因与解决

### 2.1 现象（本会话实测，photo 7d + profile 63）

- **不指定视图** `/compare`：`inferredView=""`、`selectedView=""` → 自动视图识别**完全没推断出视图**；退回整页级比对（`geometryMethod=no-quad`，无配准），10 个 mark 全比、位置不可信（counts：NA3 / Miss4 / Low3）。
- **同一照片显式 `view=TopCover`**：`selectedView=TopCover` → `FilterByView` 只比该面 8 个 mark，立即得到有效判定（Matched=2 / Missing=4 / Low=1 / NA=1）。
- **直接跑感知管线** `observe_file(photo7d)`：OCR 文本=`服务热线：400-620-6607 7()NFC便捷控制`(0.76)、`YCWA15NCWQ`(0.89)、`APP下做`(0.71)；**QR 解码=空**。

### 2.2 根因（≥2 独立角度交叉验证）

- **角度1·代码逻辑**：`InferViewFromBlind`（`MarkVerifier.cs:111–161`）只靠"盲检 OCR 文本 / QR 是否**恰好唯一**命中某视图的 mark"判定；**0 个命中 → null，多视图冲突 → null**。它不是视觉/几何识别，是文本巧合匹配。
- **角度2·真实检出**：photo 7d 的 OCR 中"服务热线"对应某视图、"YCWA15NCWQ"对应另一视图 → **多视图冲突 → null**；QR 又解不出 → 无第二信号。这正是推断为空的直接原因。
- **角度3·设计文档自认**：M6 试点说明（版本记录 #6 第623行）明确"**必须选择对应的产品面**，否则位置比对按整页布局算，仍可能误报缺标"。
- **角度4·历史验证**：#8 证明真实照片 QR 三检测器+多尺度全失败；项目记忆：RapidOCR 极端长宽比文本条带 0 检出、平面图纸勿做透视矫正。

**根因定性**：所谓的"自动视图识别"是一个**脆弱的文本/QR 巧合匹配器，不具备真正的部位识别能力**；而真实物理件照片的 OCR/QR 又不可靠，导致推断**几乎必然失败**，只能回退人工选面。

### 2.3 解决方向（可行、可落地，按性价比排序）

- **R1（推荐·最稳）型号代码锚定视图**：本照片 OCR 已检出 `YCWA15NCWQ`（型号）。建立"型号 → 该图纸各视图 mark 几何布局"索引，照片一检出型号即可**直接锚定视图**，比文本巧合稳得多，且不依赖人工。（改动集中在 `InferViewFromBlind` 增加型号→视图查表分支。）
- **R2 视觉/几何视图分类器**：以各视图渲染图为模板做特征匹配 / 轻量分类，输出 Top-1 + 置信度；低置信再降级人工。需建模板集（与 F 合并）。
- **R3 多信号融合投票**：OCR 文本 + QR + 型号 + 已匹配 mark 的几何一致性联合投票，避免"单信号冲突即 null"。
- **R4 推断置信度回传 H5**：推断失败时强制人工选面（现状），但把"推断置信度"回传前端，**低置信才弹选视图**，而不是每次都选。

## 三、对比标示错误（假红/坐标塌陷）— 根因与解决

### 3.1 现象（本会话实测，photo 7d / TopCover）

- 4 个 **Missing（红）**：`#003 禁止强电`、`#004 地暖阀`、`#005 DC15/24V`、`#006`（组合项）→ 理由均为"**定点区域未 OCR 到任何文本，全图亦未发现声明内容**"。
- 这些文字在照片里 OCR **确实没读到**（读到的是服务热线/YCWA15NCWQ/APP下做），属**实物丝印小/低对比导致 OCR 漏读**；系统无法区分"真缺"与"读不到" → **假红警**。
- `#003/#004/#005` 的 `expectedBbox` **完全相同** `[0.893, 0, 0.107, 0.090]`：组（Group）子项未算各自视图框、继承组 viewBbox → **位置对比精度塌陷**，无法区分同组 mark。

### 3.2 根因

- **角度1·判定逻辑**：`VerifyText` 在定点 + 全图盲检都未命中声明文本时判 **Missing（红）**。当照片整体 OCR 偏弱（只读出部分文字），未读到的 mark 一律红，**无"未检出-待复核"中间态**。记忆中的"宁黄勿红"只覆盖"OCR 读到疑似误识"（如 地暖阀→地暖烟），**不覆盖"OCR 完全没读到此文本"**。
- **角度2·坐标**：`Group` 子项 `viewBbox` 未计算，全部复用组框（M6 遗留，版本记录 #6 第696行"viewBbox 精度有限"；#10 坐标系修正未触及组子项）。
- **角度3·历史**：#7 已记载"服务热线/QR 假红→LowConfidence"修正，说明假红是**已知反复问题**；QR 在真实照片仍 LowConfidence/Missing（#8）。

### 3.3 解决方向

- **S1（关键）扩充"未检出"中间态**：当照片**整体 OCR 有产出**（说明照片可读）但某声明 mark 文本未命中时，判 `NotDetected`（黄/需复核）**而非直接 Missing（红）**；仅当照片整体无文本 / 质量差才允许 Missing。即把"宁黄勿红"从"疑似误识"扩展到"整体可读但单项未检出"。
- **S2 组 marks 逐子项算 viewBbox**：`MarkBuilder.InferView` 已给 mark 赋 `viewBbox`，但 Group 子项可能未赋；补齐后消除 `expectedBbox` 同值塌陷（涉及 `MarkBuilder.cs` + `V2Store.view_bbox` 写入）。
- **S3 OCR 能力升级**：① 极端长宽比/小丝印条带"四周加白边 ≥64px"（记忆已验证可恢复 RapidOCR 检出）；② 提高预处理（超分/二值/CLAHE）；③ 评估更强 OCR 模型。
- **S4 QR**：沿用 #8 多检测器 + `ink_ratio` 辅助，真实照片近距离/高分辨率复测；仍不可解则降级 `NotDetected` 而非 Missing。

## 四、关于"长期依赖用户确认"的评价与必须达到的生产可用标准

**评价**：当前人工介入有两层——
1. **必须人工选产品面（视图）**——本应是自动的（见 R1–R3）；
2. **G1 复核闸门**要求人工"确认图纸对象"，且大量 LowConfidence/Missing 需人工 adjudicate。

这在**算法调初期合理**（用人工标注反哺算法、避免假红流入生产），但作为**生产终态不可接受**：选视图本应自动；对比结果应"高置信直接采信、低置信才人工"，而不是"默认不可信、处处要人确认"。

**生产可用门槛建议（量化，对应设计文档 §10 验收标准）**：

| 指标 | 生产可用门槛 | 现状（本会话） |
|---|---|---|
| 自动视图识别准确率 | ≥ 95%（无需人工选面） | **≈0%（真实照片推断为空）** |
| 实物 mark OCR 召回 | ≥ 95% | 低（photo7d 4/7 声明文本未读出） |
| 假红率（误 Missing） | ≤ 5% | 高（4 个 Missing 疑似全假红） |
| 高置信判定占比（可直接采信） | ≥ 90% | 低（大量 Low/Miss 需复核） |
| 在线匹配 p95 | ≤ 10s（§10） | 未量化 |

> 达到上表前，系统只能定位为"**人工辅助比对工具**"；达到后才是"**首件自动比对**"。
