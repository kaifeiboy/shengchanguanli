## 二、偏差 A：比对对象混入了"非产品打标"内容（对应投诉 1）

### A1. `R4` 图面候选链违背设计 §1（关键）
设计 §1：只有出现"激光打标/镭雕/服务热线/二维码"等**关键词**，或存在**指向产品表面的引线**时，附近文字/二维码/图标才作为候选对象；标题栏、修订记录、图纸编号、技术要求、尺寸、公差默认不进入。

当前 `MarkBuilder.cs` 的 `R4`（`MarkBuilder.cs:213-237`）：当图纸**无条款声明**（`declared.Count==0`）时，把"排除标题栏带 / 尺寸 / 修订 / 噪声 / 注释"后的**全部剩余文本块**当作候选 mark（`required=false, conf=0.35`）。这是一张大网，会捞进图纸批注文字。

**实证**（库数据）：profile 55 两条 R4 候选即你说的"QR 的说明性文字"：
```
[R4] "为二维码，生产规则为设备ID，一机一地址，示例：    ， 虚线框不打印。"
[R4] "b为设备ID，一机一地址，示例：0224e9b18b7535f0，虚线框不打印。"
```
这两条是 QR 旁边的**说明性文字**，不是产品表面激光打标内容，却进入了比对对象清单。

### A2. `R4` 排除词/句式不完整
- `IsQrDecl`（MarkRules.cs:219）只匹配"二维码…格式/打印格式/打标格式"。而"为二维码，生产规则…"不含这些词 → 漏过，未被排除。
- `KnownContent`（MarkRules.cs:101-110）仅 6 项（服务热线/MAC/禁止强电/地暖阀/DC15-24V/二维码）。真实打标内容若不在此表、又不在条款声明里 → 被漏检（→ 投诉 2 的"真实部位没匹配到"）。
- 噪声排除（MarkRules.cs:242-249 `NoiseWords`）未含"示例/虚线框不打印/生产规则/一机一地址/设备ID"等 QR 说明性句式。

### A3. 设计 §3"人工复核可增删改对象"未完整实现
现有复核端点 `POST /profiles/{id}/review`（DrawingsV2Module.cs:154）只能切 `is_active` / `confirmed`，**不能新增、不能修改 text/type/view/required/condition**。
→ 批注候选进入比对前，缺少"改/删"能力，只能整体开关；且 R4 候选默认就在比对清单里显示，造成混淆。

**RuleId 分布实证**（79 条有效 marks）：
```
R4=30  R2=12  R3-qr=13  R3-icon=12  R1=1  R1-scope=6  R2-group=5
```
R4 占 38%，是批注/说明类泄漏的主要来源。

## 三、偏差 B：找图块与坐标配准远弱于设计（对应投诉 2）

### B1. 设计 §5"第一步·找图块"未实现
设计 §5：照片先根据"固定文字集合 / 文字布局 / QR 数量 / 图标数量 / 对象相对位置 / 产品轮廓"从当前型号图块中**打分选最匹配图块**；多候选接近时 H5 让用户选部位。

当前只有 `InferViewFromBlind`（`MarkVerifier.cs:168-233`）：一个**OCR 文本巧合匹配器**——盲检 OCR 文本恰好命中某 mark 的 `Text` 才推断视图；**0 命中或多视图冲突 → 返回 null → 降级页面级**。
→ 这是"常匹配不到真实部位"的直接根因：照片 OCR 稍弱、或多视图文本冲突，就推断失败。

### B2. 设计 §5"轮廓/孔位/面板基准点配准"未实现
`AnchorTransform`（`MarkVerifier.cs:132-158`）注释（§120-126）自承：轮廓/孔位基准点经实测不可行（图纸侧 `v2_drawing_views` 无几何字段、照片侧 3 张真实照片基准点候选 0/3），**改用 OCR 文本作锚点**。
- 锚点 `<3` → 不配准，坐标直映照片 → 取景差异变错位。
- 你观察到的"只有服务热线+型号能匹配"恰印证此点：这两类是**仅有的能被 OCR 稳定检出的文本锚点**，锚点≈2，映射勉强/错位；其余部位因缺锚点而失败或错配。

### B3. 多候选处理退化
设计 §5 要求"多候选接近时 H5 让用户选部位"。当前退化为"人工选视图"，且因 B1 推断常失败而需频繁手动，体验差。

## 四、偏差 C：QR 规则与设计 §7 相反（需你拍板）

- 设计 §7：二维码**不读取具体编码内容**，只检测存在性/外接矩形/方向/中心位置；**内容不同不影响通过结果**。
- 当前 #18（本会话早前）新增 `VerifyQr` 内容比对：录入预期码则比对，不同 → `LowConfidence`（宁黄勿红）。
- 这与设计 §7 冲突。需你确认：回退到设计意图（只验存在/位置，内容不影响结论），还是保留"录入预期码时做提示性比对（不判红）"。

## 五、改善方案（分 5 阶段，逐步修复，全部限于 DrawingsV2）

### Phase 1 —— 图纸侧：应打标对象 = 产品表面打标（治本，对应 A；低风险，纯 C#/规则，不改判定契约）
1. **重构 R4**：不再"排除后全候选"，改为"仅当文本块落在某视图包围盒内、或邻近图像对象/存在指向产品表面的引线"才候选；候选默认 `required=false` 且在 UI 明确区分"候选/已确认"。
2. **扩充排除词与句式**：QR 说明性文字（为二维码/生产规则/一机一地址/示例/虚线框不打印/设备ID）、字段名标签、注/说明/版本/日期/签名等；增加"块是否落在视图区域 + 有无引线"的二次校验。
3. **补全设计 §3 复核能力**：`/review` 端点支持新增/修改/删除 mark（text/type/view/required/condition），让批注在被确认前可改/删。
- **验收**：用 profile 55 同类图纸复测，R4 候选中"QR 说明性文字/标题栏/技术要求"类文本 = 0 条进入比对清单。

### Phase 2 —— 找图块 BlockMatcher（对应 B1/B3；收益最大，改动较大）
1. 实现**特征级候选打分**：照片检出 固定文字集合 + 布局 + QR 数 + 图标数 + 相对位置 + 产品轮廓 → 与当前型号各图块打分排序取 Top-N。
2. **身份锚定强化**：型号代码 / QR 解码作为强锚（扩展现有 `identityViews` 思路到图块级打分）。
3. 多候选 → H5 让用户选部位（设计 §5）。
- **验收**：实测照片"找不到真实部位"比例从当前大量 null 降级，降到可接受（目标 ≥95% 自动或一次点击命中）。

### Phase 3 —— 几何配准（对应 B2；坐标映射错误）
1. **拓宽锚点来源**：图标位置、QR 位置、产品轮廓角点、已知标记相对几何一起作锚点；OCR 文本仍可用但不再是唯一来源。
2. 锚点 `<3` 或残差 > RMS 阈值 → **降级并明确标"需人工复核坐标"**，不硬给错误映射。
3. 视图级配准 + 多锚点仿射，限幅尺度比与残差。
- **验收**：坐标映射偏差（图纸预期框 vs 照片实际）在容差内比例 ≥95%。

### Phase 4 —— QR 规则回正（对应 C；待你拍板）
- 对齐后默认回到设计 §7（只验存在/位置，内容不影响结论）；仅在明确录入"预期码且要求校验"时做提示性比对（不判红）。

### Phase 5 —— 度量与回归（贯穿）
- 用已建真值工具链（`truth_workbook.html` + `harvest_truth.py` + `run_baseline.py`）建立验收 gates：
  **部位匹配准确率 / 坐标映射准确率 / 误标率 / 漏标率**。
