## 1. 目标与动机

### 1.1 用户拍板的硬事实（2026-09-24，作为 C 的设计公理）

1. **所有打标内容都在图纸中「产品单独部位图纸」里面** —— 用户上传的是产品一个部位的照片，要的是在图纸中找到对应部位图来对比。→ C 的图块 = **产品部位**，这是业务本质，不是优化手段。
2. **尺寸数字/标线在比对时完全放弃** —— 「在能准确识别产品部位的情况下，标线本就没有任何价值，用在这里只是辅助选取产品部位的方式」。→ C 的部位判定依据中，尺寸数字/标线**只做辅助信号**（`has_dim`），绝不进入比对内容，也不作为部位成立的主证据。

### 1.2 结构性动机

把首件比对的匹配粒度从「整图 vs 整图」降到「图块 vs 图块」，解决当前三条结构性痛点：

1. **匹配区域过大 → 假红/漏检**：当前定点 OCR 按 mark 坐标裁剪，但 mark 坐标来自图纸，配准失败（affine 点对不足）时整页罩错区（见 #37 级联失败链）。图块把「该比对的范围」显式框定，区域更小更稳。
2. **视图推断失效**：`BlockMatcher.BuildViewSignatures` 只收 `view != Unspecified` 的 mark；profile 62 的 23/24 mark 是 Unspecified → 候选集为空 → 42 例全 `needsView`。图块带部位词可重建视图证据。
3. **非打标内容无结构性出口**：二维码格式说明、技术要求、标题栏、页脚署名等本就不该比对，现在只能靠 A 在 mark 级逐个规则硬杀（覆盖窄、易漏）。图块级可整体舍弃。

| 误差类型 | 典型样本 | 根因 |

| 误留（39） | `注：二维码内容不包含程序版本号和校验和。` (draws=22)、`3.上盖顶部和下盖接线为激光镭刻工艺` (draws=28)、`7.前后壳拉开标准定为≥35N` (draws=40) | 说明文字**紧贴产品图绘制**，其矩形内自然包含产品线条 → 几何失效，**只能靠文本语义识别** |

#### 2.3.4 结论：两级架构（建议作为 Phase 1 的实现 spec）

```
第 1 级 · 几何（新增，本次实测）：区域矢量条数>=25 / 是图像 / 距边缘>=20%
        → 低成本、无需渲染、覆盖 93% 判定；把「一个 OBJECT 是否属于某个产品部位」变成可计算量
第 2 级 · 文本语义（已有）：复 MarkRules.PollutionReason + blocks.py 的
        _block_is_titlebar/_block_is_techreq/_is_pure_explanation
        → 专治「紧贴产品图画的说明文字」这 7% 尾量
```
> ⚠️ 两级都必须**先过 §2.4 坐标统一**（不同 PDF 旋转不同）。

### 2.4 ⭐ 新发现：/Rotate 坐标系坑（C 落地前必须解决）

这批 PDF 带 `/Rotate 270`（profile 62 实测），存在**三套坐标系**：

| 坐标系 | 来源 | 尺寸（profile 62） |
|---|---|---|
| 显示系（= DB `bbox_json`/`norm_*`） | `page.rect` | 842×595 |

- 反变换（rot=270）：`X = W0 - y'`，`Y = x'`（W0 = mediabox 宽）。已验证：mark「服务热线」bbox_json → 原始系 Rect(178.06,213.08,183.31,307.23)，矩形内精确命中 `['PC-P1HJQ','服务热线：','4008601111']`。

- **C 落地前置任务**：统一坐标系（建议全部归一到显示系；`blocks.py` 接入时用 `page.derotation_matrix` 做变换，并用「服务热线」mark 做回归锚点）。

## 3. 逻辑图块定义与分类

**逻辑图块** = 空间相邻、语义同类的图纸元素簇，代表一个「功能/打标区域」。聚类后每块带：
- `bbox_norm`（归一化边界框）
- `kind`：`Marking`（真实打标区）/ `TitleBar`（标题栏）/ `SpecNote`（技术要求/说明）/ `SignBlock`（署名/页脚）/ `QrZone`（二维码区）/ `Other`
- `view_hint`：块内部位词推断的视图（TopCover/BottomCover/…）
- `mark_ids`：块内 mark 列表

分类依据（直接复用 `blocks.py` 现有判定）：
- `_looks_marking(text)` 为真且非说明 → `Marking`
- `_block_is_titlebar` → `TitleBar`
- `_block_is_techreq` / `_is_pure_explanation` → `SpecNote`
- `_block_is_signblock` → `SignBlock`
- 含 QR mark 的块 → `QrZone`

## 4. 架构设计（5 项能力）

### C0（新增，前置）：坐标系统一
- 见 §2.3。`blocks.py` 接入前先把 `get_text`/`get_drawings` 坐标统一到显示系（DB mark 坐标所在系）。
- **回归锚点**：profile 62 mark「服务热线」bbox_json → 原始系矩形内必须精确命中 `['PC-P1HJQ','服务热线：','4008601111']`。

### C1 图纸侧图块聚类（复活 `blocks.py`）
- `MarkBuilder.Build` 产出 marks 后调用 `extract_blocks(pdf, thr_pt=38.0)`，把 mark/文本/图像聚成图块。
- 聚类参数 `thr_pt=38` 是经验值，**须用真值集标定**（见 §8）。
- 替代当前 `GroupBlocks` 的 `BlockIndex` 分组。
- **⚠️ 实测修正（§2.1）**：39% 打标文字不在文本层 → 聚类输入不能只有文本层 items，必须并入「转曲区渲染 OCR bbox」（P0-1 fallback 已能产出）+ 图像 items。C 类（2 份全页无文本层）**只能**靠 OCR bbox 聚类。

### C2 匹配粒度降到图块级
- 定点 OCR 裁剪框从「单 mark 坐标」改为「mark 所属图块 bbox」（区域更大但更聚焦，罩错区概率下降）。
- 同图块内多 mark 可共享一次 OCR 结果（性能收益）。

### C3 结构化 coverage 判据（替代 B 的 subject 求交）
- B（#37）用「mark 期望位置 vs photo subject」求交，已后置且仅翻 Missing/NotDetected。
- C 升级为「**图块 bbox vs photo subject**」求交：整块未拍到 → 块内全部 mark 标 `NotApplicable`（灰），比逐 mark 更稳、更符合「未拍到该部位=灰」（方案 §8）。
- 与 B 关系：C 落地后 B 的逐 mark 求交可保留为兜底或退役（待拍板）。

### C4 非图块区域结构性舍弃（与 A 协同）
- `TitleBar`/`SpecNote`/`SignBlock` 块整体不进入比对（不产 verdict），彻底解决「二维码格式说明/页脚署名」污染。
- 与 A 分工：A 在 mark 级清理**兜底链（R4/R5-vision）**污染；C 在图块级清理**主链路非打标区**。两层互补，覆盖更全。

### C5 视图推断增强
- 图块级 `view_hint`（块内部位词）喂给 `BlockMatcher.InferView`，解决 Unspecified 失效：即使 mark 未标 view，其所属图块可给视图证据 → 候选集重建。
- 直接改善 #37 暴露的「42 例全 needsView」。

## 5. 数据结构

重建 `v2_drawing_blocks`（清掉 118 行旧残留）：
```
v2_drawing_blocks(
  id, profile_id, block_idx,
  kind TEXT,                 -- Marking/TitleBar/SpecNote/SignBlock/QrZone/Other
  bbox_norm TEXT,            -- [x,y,w,h]  ⚠️ 显示系（与 DB mark 坐标一致，见 §2.3）
  view_hint TEXT NULL,
  mark_ids TEXT,            -- JSON 数组
  created_at
)
```
`v2_drawing_marks` 加列 `block_id INTEGER NULL`（关联所属图块）。

> 坐标系约定（§2.3）：**所有落库 bbox 一律显示系**；`blocks.py` 内部坐标在出口处统一变换，进口处（OCR bbox、文本层 items）在入口处统一变换。

## 8. 风险与待确认

1. **聚类参数 `thr_pt` 需真值集标定**：间距阈值错了会把多个打标区并成一个或拆碎 → 直接影响 C2/C3 效果。**无真值集前不可上线**（与 #37 根卡点同源）。
2. **`blocks.py` 354 行可能过时**：基于旧解析器产出，需先 review 是否适配当前 `VectorPdfParser` 输出（文本/图像 items 结构）。
3. **⭐ 坐标系坑（§2.3）是落地前置**：不统一坐标，块 bbox 与 mark 坐标错位 ~4% 量级 → C2/C3 全线失真。必须先做 C0 + 「服务热线」锚点验证。
4. **39% 打标文字不在文本层（§2.1）**：纯文本层聚类会漏块 → C1 必须并入 OCR bbox 与图像 items；这也意味着 C1 的效果依赖渲染 OCR 的覆盖（与 P0-1 fallback 产出对齐）。
5. **回归风险**：图块匹配改动比对主链路，须真值集证明召回不降、假红不升。
6. **与 B 的关系**：C3 落地后 B 的逐 mark subject 求交是否退役（建议退役，避免双判据冲突）。
7. **范围拍板**：本次先做 C1+C4（性价比最高：结构性舍弃非打标区 + 聚类框架），还是一步到 C5（视图增强，直接解 needsView）？建议分期。
