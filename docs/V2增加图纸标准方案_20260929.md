# V2 增加图纸标准方案（2026-09-29）

> 目标：在删除 V1 之前，为 V2 定制一套**适合 V2 技术特点**的「增加图纸 / 库管理」方案，
> 取代 V1 的 `add-batch` + `sync`。本文件先确立标准与待确认决策，确认后再落地代码。

## 0. 事实基础（代码实测，非推测）

| 维度 | V1（待删） | V2（现状） |
|---|---|---|
| 写图纸文件 | ✅ `AddDrawing` 落盘到 `Files:Root`（`E:\生产打标效果图`） | ❌ **无任何写文件能力**，只读 `Files:Root` 已存在 PDF |
| 登记动作 | 落盘 + `INSERT(MODEL,FileName,VirtualPath)`，**无解析、无 OCR、无复核** | `/analyze` → Python 解析 → `MarkBuilder.Build` → `SaveProfile`（profile+views+marks，status 默认 `draft`） |
| 匹配所需数据 | 坐标对齐用的 mark views（解析即得） | **逻辑块（OCR 抽出的文本段）**，独立步骤 `ExtractLogicalBlocksAsync`，27~62s/张 |
| 逻辑块抽取时机 | 不需要（坐标匹配） | 目前靠 `compare` **懒触发**；若从不比对则永远无块 |
| 去重口径 | 按 `VirtualPath` 字符串 | 按 `(drawing_key, pdf_sha256)` → 复用 profile、替换 views/marks、内容变化则重置 `draft` |
| 复核状态机 | 无 | 有：`status` ∈ `draft`/`reviewed`（reviewed_at/by/note） |
| 型号/选择键 | `Model` 字段（从文件名解析） | `drawing_key`（=文件名去扩展名），H5 型号驱动已基于它 |

**关键现状**：全库 21 个 profile 中仅 10 个已抽逻辑块，11 个 `blocks=0`（含 52/61/62/63/64/65/66 已 reviewed 但部分 0 块，67 draft 有 6 块）。
→ 结论：**V2「增加图纸」必须把逻辑块抽取作为一等公民纳入流程**，不能只登记。

## 1. 标准原则（拟定）

1. **复用同一图纸根目录**：新增文件落盘到 `Files:Root` 的 `drawings/{文件名}.pdf`，沿用 `ResolvePdf` 解析约定，不另起目录。
2. **安全落盘**：PDF 魔数校验、文件名 `SanitizeFileName`、同名自动加 `_k` 后缀去重，落盘失败结构化报错（不抛 500、不遗留孤儿文件）。
3. **登记即解析**：新增即跑 `AnalyzeAsync`（解析+建 mark+SaveProfile），复用其 `(drawing_key, sha256)` 去重，内容变化自动重置 `draft`。
4. **逻辑块抽取必须纳入流程**：登记后主动触发/入队 `ExtractLogicalBlocksAsync`，不依赖「首次比对才抽」。
5. **异步可观测**：抽取是重活（27~62s/张，批量分钟级），必须异步化并有状态/进度可查；`compare` 懒触发作为兜底保留。
6. **状态机显式**：新增 `blocks_status`（pending/extracting/ready/failed）独立于 `reviewed`，H5 可展示「解析中 / 抽取中 / 就绪 / 失败」。
7. **两入口并存**：上传（单/批量）+ 目录扫描（sync），行为一致（落盘→登记→入队抽取）。只增不删。

## 2. 推荐流程

```
[上传/扫描]
   │
   ├─ 落盘 drawings/{safe}.pdf（校验+去重）
   ▼
[AnalyzeAsync]  → profile(status=draft) + views + marks
   │  (复用 sha 去重：同文件重传→复用 profile，重置 draft)
   ▼
[入队 ExtractLogicalBlocksAsync]  → blocks_status: pending → extracting → ready | failed
   │  (后台 Task/队列；超时沿用 BlocksTimeoutMs=600s)
   ▼
[返回] profileId + drawing_key + blocks_status
```
- H5「图纸库」列表展示：型号(drawing_key)、状态徽标（`draft/reviewed` + `抽取中/就绪/失败`）、块数。
- `compare` 命中 `blocks=0` 仍懒触发抽取作为兜底（现状不变）。

## 3. 端点设计草案（落在 `DrawingsV2Module`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/drawingsv2/profiles/import` | multipart 上传（单/批量同名 `file` + 可选 `model`），逐张落盘→登记→入队，返回每张结果 |
| POST | `/api/drawingsv2/profiles/sync` | 扫描 `Files:Root`，对库缺文件跑同上，返回 added/skipped |
| GET  | `/api/drawingsv2/profiles/{id}/blocks/status` | 查 `blocks_status` 与进度（已抽块数/总页） |

## 4. 待确认决策点（见对话确认）

- D1 逻辑块抽取时机：异步队列（推荐）/ 同步阻塞 / 仅懒触发
- D2 复核门禁：draft 可否直接比对（推荐，贴近 V1「加了就能用」）/ 必须 reviewed 才允许
- D3 目录扫描 sync 是否保留（推荐保留）

> 注：`model` 独立字段**不建议新增**——V2 型号驱动已基于 `drawing_key`（文件名去扩展名），
> 与 H5 #107–#111 一致；若需友好展示名，后续可在 profile 加 `display_name` 可选列。
