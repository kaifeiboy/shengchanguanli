# 项目最初实施方案（原设计文档整理）

> 来源：`矢量PDF图纸信息提取与激光打标匹配项目方案.md`（桌面最初版本）
> 用途：作为 DrawingsV2 模块开发的事实基线。本文档按原方案原文整理，仅做结构化拆分，不增删设计意图。
> 对照：差异见 `docs/设计vs实现差异.md`。

---

## 1. 图纸解析方案

- 以 PDF 原生数据为主。AutoCAD 导出的矢量 PDF 读取：页面方向、文字字符、文字坐标、字体、字号、旋转角度、线段、矩形、路径、图片对象。
- 页面坐标统一转换为**横向标准坐标**，后续对象共用同一套坐标系。
- 页面先划分成**产品视图**和**局部区域**，再从视图提取**打标对象**。
- 默认不进入打标对象的内容：标题栏、修订记录、图纸编号、文件编号、技术要求、发放部门、普通尺寸、公差。
- 出现以下信号才把附近文字/二维码/图标作为候选对象：
  - 关键词「激光打标」「镭雕」「服务热线」「二维码」；
  - 指向产品表面的引线。
- 文字来源优先级：
  - 正常矢量文字 → 直接从 PDF 提取，**不使用整页 OCR**；
  - 二维码/图标 → 只记录图片或图形位置与尺寸，**不解析具体内容**；
  - 仅当文字已转轮廓线、PDF 对象损坏或原生解析无法确认时，才对对应小区域做**局部图像识别**，并在数据中记录「该对象来自视觉兜底」；
  - 扫描 PDF / 无法解析文件 → 使用现有渲染 + 局部识别流程，不阻塞矢量 PDF 主流程。

## 2. 应打标对象模型

- 图纸内容整理成「应打标对象」，每个对象独立保存，不把一张图片当作唯一业务数据。
- 对象类型 `type`：`text`（固定/多行文字）、`qr`（二维码）、`icon`（电源/警示/按键等图标）、`group`（同区域内多行文字+二维码+图标的组织）。
- `group` 用于找图块，组内成员仍单独参与匹配。
- 标准对象字段（示例）：

```json
{
  "id": "top_text_01",
  "model": "PC-P1HJQ",
  "view": "top_cover",
  "type": "text",
  "text": "PC-P1HJQ",
  "required": true,
  "condition": null,
  "bbox": [120, 80, 86, 18],
  "direction": 0,
  "source": "pdf_vector",
  "confidence": 1.0
}
```

- 固定文字：保存标准文本 + 位置（如型号、服务热线、`LOW VOLTAGE`、`禁止强电`、`DC15/24V`）。
- 二维码：**不保存必须相同的编码字符串**，只保存类型、位置、大小、方向、是否必检。
- 条件标识：保存适用型号/适用条件（某标识只适用于指定型号）。
- 坐标：同时保存**图纸原始坐标**与**归一化坐标**，便于不同尺寸/渲染比例下做位置映射。

## 3. 图纸确认和管理

- 上传后进入解析状态；解析完成在管理页显示原图、视图划分、识别出的打标对象。
- 管理人员可：新增/删除/修改对象，修改类型、文字内容、所属视图、是否必检、适用条件。
- **确认后的对象清单才允许用于生产匹配**。
- 图纸库检索维度：产品型号、产品名称、图纸编号、状态。
- 每个型号可关联 1 份当前有效图纸 + 多个历史图纸；生产匹配默认只用当前有效版本。
- 详情页：完整图纸、视图列表、打标对象列表、局部图块；点击对象定位到图纸具体位置。

## 4. 图块生成

- 图块以**产品视图**或**打标区域**为单位生成。
- 每个图块保存：完整局部图、打标对象透明层、视图名称、基准点、比例、方向、对象列表。
  - 完整局部图 → 手机展示；透明层 → 绘制匹配结果。
- 图块需记录的特征：固定文字集合、二维码数量、图标数量、对象相对位置、视图长宽比、产品轮廓。
- 照片上传后**先按这些特征选候选图块，再进入详细匹配**，避免与型号下所有图块逐一高成本比对。

## 5. 照片处理和图块匹配

1. **质量检查**：清晰度、亮度、主体大小、遮挡程度、目标区域是否完整。
   - 不满足 → 返回「请重新拍摄」，**不直接判定缺标**。
2. **预处理**：检测文字区域 / 二维码区域 / 图标区域 / 产品轮廓，执行**旋转校正、透视校正、尺度归一化**。
   - 平面 PVC 盖子优先用**边框、孔位、面板轮廓或其他稳定结构作为基准点**。
   - 无法找到足够基准点 → 降低匹配置信度，要求人工复核。
3. **两步匹配**：
   - 第一步「找图块」：根据照片中固定文字、文字布局、二维码数量、图标数量、对象相对位置、产品轮廓，从当前型号图块选最匹配图块。
     - 单候选且置信度达阈值 → 自动进入下一步；
     - 多候选接近 → H5 让用户选择对应部位。
   - 第二步「验标」：图块中每个应打标对象与照片实际对象建立**一对一关系**。
     - 文字逐字比较；二维码/图标只比较存在性与位置；
     - 所有结果保留**对象级明细**。

## 6. 文字匹配规则

- **安全归一化**：全角半角统一、大小写统一、首尾空格清理、连续空格合并。
  - 不随意替换：数字、字母、斜杠、连字符、加减号、直径符号、单位。
  - `0/O`、`1/I` 等易混字符 → 记**低置信度**，不能直接视为相同。
- **两类文字**：
  - 固定文字 → 逐字一致；
  - 可变化文字（日期/批次号/流水号）→ 保存**格式规则**，只校验长度、字符范围、格式，不要求与图纸示例完全相同。
- **区间级结果**：保存正确字符区间、错误字符区间、缺失区间、多余区间；渲染时只标示对应区段。
- **照片侧识别约束**：
  - 手机照片无 PDF 字符对象，必须识别文字；
  - 识别结果须保存**字符坐标 + 置信度**，不能只存一整段字符串；
  - 置信度过低 / 字符区域被遮挡 → 返回**待复核**，不直接返回缺标。

## 7. 二维码和图标匹配规则

- **二维码不读取具体编码内容**，只检测：照片中是否存在二维码、外接矩形、方向、中心位置。
- 图标同规则：只比较是否存在、类别是否大致一致、位置是否对应。
- 标示逻辑：
  - 图纸和照片都有，且位置误差在允许范围内 → **不绘色**；
  - 图纸要求有、照片没有 → 照片对应位置绘**黄色**；
  - 照片有、图纸没有 → 照片多出区域绘**黄色**（extra）；
  - 两者都有但位置明显偏移 → 黄色 + 提示**人工复核**；
  - **二维码内容不同不影响通过结果**。

## 8. 结果标示规则

- 四色语义：
  - 绿：对象已找到，文字逐字一致，或二维码/图标存在且位置正确；
  - 红：图纸要求的文字缺失、文字错误、明确位置错误；
  - 黄：二维码/图标一侧存在一侧不存在、位置偏差较大、照片质量不足、识别置信度不足；
  - 灰：仅用于不适用、未拍到该部位、当前无法比较的对象，**不代表合格**。
- 照片标示结果与图纸块标示结果**使用同一个对象状态**。
  - 照片显示现场实际问题，图纸块显示对应要求位置。
- 结果页返回：标示后的照片 + 匹配到的图纸块 + 对象级明细。
- **后端状态枚举**：

```
matched / missing / wrong / extra /
low_confidence / not_applicable / not_comparable / processing_error
```

- **整体结论汇总规则**：
  - 存在红色 → 不通过；
  - 无红色但存在黄色 → 待复核；
  - 全部必检对象为绿色 → 通过。

## 9. H5 页面流程

- 首页入口：产品型号检索、拍照、从相册选择。
- 选型号后固定显示当前型号 + 图纸名称，进入拍照页。
- 拍照页：拍摄、相册、重拍、裁剪，并提示需拍摄的部位。
- 处理页依次提示：「正在定位产品部位」「正在匹配图纸图块」「正在核对打标文字」「正在检查二维码和图标」。
- 结果页：整体结论 + 标示后现场照片 + 匹配到的图纸块；点击红/黄/绿区域查看对象名称、图纸要求、照片识别结果、判断原因。
- 单部位照片只返回该部位结果；可继续上传其他部位，多张照片合并到同一检验记录。
- 适配手机屏，主要按钮易点；返回/重拍/换型号/保存记录/查看详情遵循正常手机操作逻辑。

## 10. 历史记录

- 每次匹配记录保存：产品型号、图纸版本、操作人员、时间、原始照片、标示后照片、匹配图块、对象级结果、整体结论。
- 详情页可同时查看原始照片、标示照片、图纸块，并定位到具体红/黄/绿对象。
- 支持按型号、时间、操作人员、结果筛选。
- **必须保留当时使用的图纸对象清单和匹配参数**，不能只存当前图纸（否则图纸更新后无法还原历史判断）。

## 11. 系统模块划分

- 后端保留现有 .NET API + SQLite 为基础，新增/调整模块：

| 模块 | 职责 |
|---|---|
| `VectorPdfParser` | PDF 原生内容解析 |
| `DrawingMarkBuilder` | 视图识别 + 应打标对象生成 |
| `DrawingReviewService` | 图纸人工确认 |
| `PhotoObservationService` | 照片质量、文字、二维码、图标、轮廓检测 |
| `BlockMatcher` | 候选图块 + 对象匹配 |
| `DiffRenderer` | 照片及图纸块标示 |
| `DrawingRepository` | 图纸 / 对象 / 结果存储 |
| `HistoryRepository` | 历史记录存储 |

- 数据库至少包含：

```
drawings
drawing_views
drawing_marks
drawing_mark_groups
match_sessions
match_observations
match_results
drawing_histories
```

- 图片只用于展示，**判断依赖结构化对象与结果数据**。

## 附：关键实现要点速查（落地清单）

1. **坐标系**：页面统一转横向标准坐标；对象同时存原始坐标 + 归一化坐标。
2. **对象类型**：`text` / `qr` / `icon` / `group`；`group` 用于找图块，成员独立匹配。
3. **图纸解析**：优先 PDF 原生，禁用整页 OCR；轮廓/损坏区域才局部识别并标 `source=视觉兜底`；QR/图标只记位置不解析内容。
4. **非打标过滤**：标题栏/修订/图号/文件号/技术要求/发放部门/普通尺寸/公差默认不入对象；靠关键词或引线激活候选。
5. **图块特征**：固定文字集、QR 数、图标数、相对位置、长宽比、产品轮廓 → 用于候选筛选。
6. **照片质量**：不达标返回「请重新拍摄」，**绝不判缺标**。
7. **基准点**：平面 PVC 优先边框/孔位/面板轮廓；不足则降置信 + 人工复核。
8. **两步匹配**：找图块（自动/人工选面）→ 验标（一对一，文字逐字、QR/图标比存在+位置）。
9. **文字规则**：安全归一化；`0/O`·`1/I` 低置信不视同相同；可变文字只验格式不验内容；保存正确/错/缺/多**字符区间**；照片侧须存字符坐标 + 置信度。
10. **QR/图标规则**：不读内容，只比存在 + 位置；内容不同不影响通过；偏移/单侧缺失 → 黄色 + 复核。
11. **四色 + 枚举**：`matched/missing/wrong/extra/low_confidence/not_applicable/not_comparable/processing_error`；灰 ≠ 合格。
12. **汇总**：红→不通过；黄→待复核；必检全绿→通过。
13. **历史**：保留当时图纸对象清单 + 匹配参数（防版本漂移）。
14. **模块/表**：见 §11 两张表。
