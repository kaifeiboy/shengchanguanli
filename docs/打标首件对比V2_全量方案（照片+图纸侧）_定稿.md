## 0. 总体架构与数据流（1:1 部位级比对）

```
        ┌─────────────── 照片侧（模块①）───────────────┐         ┌──── 图纸侧（模块②）────┐
 上传 → │ 质量评估(原图) → 透视矫正 → 部位定位(连通域) │         │ 文本层 span+图像对象   │
 照片   │   → 区域预处理(WB+CLAHE) → 原生分辨率OCR     │         │   空间聚类 = 逻辑图块  │
        │   → TextRegion(text, norm_bbox, conf)        │         │ V2Block + candidates   │
        └───────────────┬──────────────────────────────┘         │  (含噪三步过滤 + 坐标)  │
                        │ 照片 OCR 内容集                          └───────────┬────────────┘
                        │                                               图块内容集 │
                        └─────────────── 模块③：内容命中匹配 ───────────────┘
                                     （photo tokens ↔ block candidates，命中最多=该部位；
                                       歧义→H5人工选块兜底）
                                                  │
                                                  ▼
                                    模块④：逐条比对 + 四色标示
                                     （绿=命中且位置正确 / 红=缺失或位置错 / 黄=偏移或低置信 / 灰=跳过）
                                      坐标闭环：图纸未变换 NormBbox=要求位置；照片 RebaseToView+配准=实际位置
```

**核心命题（用户已拍板）**：真实场景打标以「部位」为单位，照片拍的也是对应部位、且严格 **1:1**（一次只拍一个部位正面）。因此匹配从「整页/整视图」降为「部位↔部位」，部位由「图块（图纸侧，逻辑聚类）」与「照片部位（照片侧，连通域定位）」在内容层对齐。这正是根治诊断报告 RC2.3（退化整页）/RC3.1（照片=视图包围盒）的钥匙。

## 1. 模块② 图纸侧部位提取（结论整合，详规见独立文档）

- **三类图纸全量覆盖**：A 栅格化(17) / B 原生矢量(2) / C 文字转曲(2)，全体 = `E:\生产打标效果图` 真实 **21 份**。
- **图块 = 逻辑概念**：文本 span + 图像对象（QR/logo）按空间间距聚类（并查集 `THR≈38`）；不是 V1 物理切块。
- **噪声三步过滤**：① 标题栏满高窄列整块丢；② 技术要求整句块丢；③ 会签栏部门名丢。
- **C 类 vision_fallback**：渲染 200DPI + RapidOCR，bbox 喂入同一聚类流水线。
- **坐标**：每个候选带 `norm_bbox∈[0,1]`（原设计「归一化坐标」）+ 可选 `orig_pt`（原设计「图纸原始坐标」）；图块带 `anchor_norm`（优先块内 QR 中心）供配准。
- **提取时机**：建档案期一次性完成（含 C 类渲染 +1.4s/页），比对期只读库，不增加比对固定开销（当前 ~6.5s/请求）。
- 详见 `docs/打标首件对比V2_图纸侧部位提取方案_定稿.md` §1–§12。

## 2. 模块① 照片侧预处理与部位定位（**本次新增定稿**）

### 2.1 范围与硬约束（用户澄清）

| 项 | 约定 |
|---|---|
| 严格 1:1 | 一次只拍一个部位正面照；照片对应图纸中唯一图块 |
| 背景 | 产品单色底、无复杂背景；**不做背景分割** |
| 物理裁剪 | **不做**（不落盘裁剪文件）；预处理在内存 ROI 上做，仅计算坐标 |
| 反光 / 低对比 | 当前阶段由用户自理（不自动处理） |
| 无背景情形 | 只需**定位文本部分**做处理与识别即可 |
| 源文件夹 | 只读（照片为用户上传，不进 `E:\生产打标效果图`） |

### 2.2 现状代码实测（不全改，只补缺口）

读 `Scripts/observe/{pipeline,quality,geometry,text}.py` 实测：

- `pipeline.observe_image`：`quality=Q.assess(原图)` → `warped=G.normalize` → `proc=_resize_max_side(warped, MAX_SIDE=1280)` → `T.detect(proc)`。
  - **RC1.1（细节损失）**：OCR 跑在 `MAX_SIDE=1280` 降采样图上，细长打标串（MAC/端子标识）易漏检误识。注释自承 1280 比原图少 4 区、960 开始丢内容。
  - **部位定位错配**：`_subject_of(texts,codes)` 用 **OCR 内容并集** 反推主体区域（`min_items=2`，不足返回 None）。诊断已证 `subject` 不能代表有效部位区域（Matched 仅 46.7% 落其内）——它应在 OCR **之后**做约束，不能作为**部位检测**本身。
- `quality.py`：**无白平衡**（WB）函数；`assess` 有 `SHARPNESS_MIN=100 / MIN_SIDE=640 / OVEREXPOSED_RATIO=0.99 / UNDEREXPOSED_RATIO=0.95 / DYNAMIC_RANGE_MIN=30`；`apply_ocr_evidence` 以 OCR 证据豁免清晰度/动态范围类拒绝（合理，保留）。
- `geometry.py`：`detect_quad / warp / _is_flat` 已就绪且 `_is_flat`（轴对齐≤4°/四角贴边±4% 跳过）为正向不误矫，复用。
- `text.py`：`T.detect` 用 RapidOCR，`MIN_CONF=0.5`，行内合并（解决长串切碎），返回 `TextRegion(text, conf, bbox, norm_bbox, angle)` —— **坐标基座已具备**。
- **既有修复须保留**：小裁剪喂 RapidOCR 须 **四周加白边 ≥64px**（极端长宽比条带 0 检出的根治法），实施时落到区域 OCR 入口。

### 2.3 新流程（取代「整图降采样 OCR + 内容并集定位」）

```
observe_part(bgr, ...):
  1. quality = Q.assess(bgr)                      # 原图，保留
  2. warped, geo = G.normalize(bgr)               # 透视矫正；平面件 flat 跳过（复用）
  3. part_region = _detect_marking_region(warped) # ★新增：部位定位（见 2.4）
  4. if part_region:
        roi = _roi(warped, part_region)           # 内存切片，不落盘
        roi = _preprocess(roi)                     # 可选 WB(灰度世界) + CLAHE 局部对比
        roi = _add_white_border(roi, 64)          # 既有修复
        texts = T.detect(roi)                      # ★原生分辨率，不降采样
        texts = _rebase(texts, part_region)       # region→image 归一化坐标
        if len(texts) < MIN_OCR_ITEMS:            # 检测可能漏 → 退化
            texts = _ocr_whole(warped)
     else:
        texts = _ocr_whole(warped)                # 检测失败绝不硬猜框
  5. codes = M.detect(roi if part_region else warped)
  6. Q.apply_ocr_evidence(quality, texts, codes)  # 保留
  7. 输出 observe/1：quality / geometry / texts(norm_bbox∈[0,1]) / codes / part_region
```

### 2.4 部位定位 `_detect_marking_region`（单色底深色笔画连通域）

- 输入：矫正后图 `warped`（灰度）。
- `gray = cvtColor(warped, BGR2GRAY)`；可选 `_gray_world_wb`（灰度世界白平衡，极廉价，先并行做一份备用）。
- 二值化：单色浅底 + 深色打标 → 取暗笔画 `mask = gray < adaptive_thresh`（自适应阈值或 Otsu 反转；对反光/低对比用户自理，WB 仅做温和补偿）。
- 连通域：`cc = connectedComponents(mask)`；过滤面积 `[Amin, Amax]`、剔除孤立噪点。
- 聚类：邻近连通域形态学闭合 → 1~数个 marking 簇；严格 1:1 取 **最大簇**（或紧邻并集）为部位区域。
- 输出 `norm_bbox∈[0,1]`（图像相对）。若无可信连通域 → 返回 `None`（触发整图退化）。
- **绝不硬猜**：任何一步无结果都降级整图 OCR，不返回错误框（硬猜会比现状更糟）。

### 2.5 退化与风险

| 情形 | 处理 |
|---|---|
| 部位定位失败（无暗笔画/全白） | 整图 OCR，不猜框 |
| 区域 OCR 文本 < MIN_OCR_ITEMS（定位偏紧漏标） | 整图 OCR 兜底 |
| 反光/低对比致 WB+CLAHE 仍差 | OCR 证据门 (`apply_ocr_evidence`) 判 `not_comparable`，请重拍，不谎报缺标 |
| 照片含多部位（非 1:1） | 退化为「整图内容集」参与模块③；提示用户按 1:1 重拍（不强制） |

### 2.6 坐标携带

`TextRegion.norm_bbox` 经 `_rebase` 后即为**图像相对 [0,1]**，与现有 `obs.Texts[].norm_bbox` 契约一致，模块③/④ 直接消费；QR 同理用 `QrNormBbox`。

### 2.7 模块① 验收

| 样本 | 期望 |
|---|---|
| 含细长 MAC/端子串的部位照 | 区域原生分辨率 OCR 召回 ≥ 整图 1280 降采样（对照 p63 LOW VOLTAGE/禁止强电/地暖阀/DC15/24V 类） |
| 单色底正常照 | `part_region` 覆盖打标文本区；`subject` 误约束问题消除 |
| 无打标/空照 | 部位定位返回 None → 整图退化，不崩溃 |
| 反光照 | WB+CLAHE 尝试后仍差 → `not_comparable` 而非假红 |

## 3. 模块③ 照片部位 ↔ 图纸图块 匹配算法（**整合新增**）

### 3.1 严格 1:1 假设

照片 OCR 内容集应精确对齐**一个** V2Block。匹配以内容为主、位置为辅（1:1 下位置已隐含一致）。

### 3.2 内容命中匹配

- 取照片 `TextRegion` 文本集合 `P = {normalize(t.text)}`（复用 `TextNormalizer` / `MarkVerifier.NearestKey` 容差：键长≤6 容差 1、更长容差 2）。
- 对每个 V2Block 取候选文本集合 `B_k = {normalize(c.text)}`（含 `c.type∈{Text,Qr,Icon}`）。
- 打分：`score_k = |P ∩ B_k|`（加权：精确命中 > 近邻命中）+ 图像对象（QR/logo）存在性命中。
- **命中最多块 = 匹配部位**。

### 3.3 歧义兜底（用户已确认接受）

- 若 `score_top1` 不显著大于 `score_top2`（如 `top1 ≤ 1.6 × top2`）或 `score_top1 == 0` → **H5 人工选块**。
- 自动模式仅作**推荐排序**（把候选块按 score 降序列出），达标（≥95%）前不强制。

### 3.4 坐标配准（复用现有基座）

- `MarkVerifier.RebaseToView` + `ViewBboxOf` + `ApplyAffineRegistration` + `EstimateAnchorTransform`(QR 锚点, P3) + `EstimateConsistentOffset`(P27) 全部复用。
- 照片侧锚点：优先 `part_region` 内 QR 中心；无 QR 用 `part_region` 四角。
- **C 类图块坐标精度低于 A/B**（norm ±0.002~0.005）→ 配准残差门 `ResidualGate` 与 `PositionOk` 容差**按类差异化放宽**，或降置信 + 人工复核（原设计「照片质量段」要求）。

### 3.5 模块③ 验收

| 样本 | 期望 |
|---|---|
| p58 约克10寸屏（原 4 mark 全 Unspecified） | 照片内容正确命中对应图块，不再 Unspecified |
| 多图块图纸拍单部位 | 命中唯一块，歧义时 H5 可人工选 |
| C 类（日立/海信） | 渲染恢复文字后参与匹配，位置容差放宽不误杀 |

## 4. 模块④ 打标内容识别与标示（整合坐标 + 原设计规则）

### 4.1 逐条比对

对匹配块 `B_match` 的每个候选 `c`，在照片 `P` 中按 `TextNormalizer` + `NearestKey` 找最近命中：
- 命中 → 进入位置判定；未命中 → 按原设计判 `Missing`（红）或经 `MarkRules` 判 `NotApplicable`（灰）。
- 图标/QR：`c.type=Icon/Qr` 只比存在性 + 位置（复用 `MarkVerifier.VerifyIcon/VerifyQr`）。

### 4.2 四色标示规则（原设计「标示段」）

| 色 | 含义 | 触发 |
|---|---|---|
| 绿 | 找到且位置正确 | 命中 + `PositionOk` 通过 |
| 红 | 缺失 / 错误 / 明确位置错误 | 未命中 或 命中但位置超容差 |
| 黄 | 位置明显偏移 / 低置信 | 命中但偏移在黄区，或 `conf<OCR_CONF_MIN` |
| 灰 | 跳过（CAD/LCD/icon/工艺批注） | `MarkRules` 噪声/非打标 |

### 4.3 坐标映射闭环（图纸侧 §12 落地）

- **图纸块**用**未变换** `c.norm_bbox`（页面坐标）绘「要求位置」—— 硬规则：图纸回显恒用未变换坐标，否则整页错位（诊断已证 7/7 画错）。
- **照片**经 `RebaseToView` + 配准后绘「实际位置」。
- `PositionOk` 判绿/红/黄：`c.norm_bbox`（要求）与照片对应 `TextRegion.norm_bbox`（实际）比对。
- C 类某候选 OCR 未返 bbox → 退回块中心 + `needsReview`，**不硬猜位置**（防假红/假绿）。

### 4.4 模块④ 验收

同诊断基线 `baseline_report_p6.json` 指标：NotDetected 率（现 33.5%）显著下降、falseGreenRate 维持 0、recall 提升；四色分布可解释。

## 8. 风险与未决项

1. **聚类阈值 `THR≈38`、标题栏宽%阈值**为经验初值，须 §7 回归定稿。
2. **C 类 bbox 聚类成图块**留实施期用日立/海信回归确认（文字恢复已实证）。
3. **照片部位定位在深色产品/低对比场景**可能退化整图——以 OCR 证据门兜住，不谎报。
4. **H5 展示最优解**待定（§5）。
