> 范围：`.NET 8` 决策/运行时层 + `Python` 感知层整体梳理
> 模块根：`src/Platform/Modules/DrawingsV2/`
> 端点前缀：`/api/drawingsv2/*`
> 配套演进记录：`docs/激光打标首件对比系统v2_版本记录.md`（已到 #27）；设计对照见 `docs/设计vs实现差异.md` / `docs/项目最初实施方案.md`

## 1. 概述

V2 是一套**独立、与旧 `drawings` 模块并存**的「激光打标首件对比」引擎。它把原来的「单照片逐字比对」升级为「图纸侧要求 + 照片侧实测 + 决策层判定」三段式管线，目标是把误标/漏标降下来、把判定从「脚本猜测」变成「可解释的证据链」。

核心设计原则（来自代码注释与实测）：

- **感知 / 决策分离**：Python 只回答「看到什么」（中性观测：文本、码、几何、质量），**绝不输出 matched/missing 这类结论**；是否合格完全由 C# `MarkVerifier` 判定。
- **图纸侧 / 照片侧对称契约**：`vpdf/1`（图纸要求）与 `observe/1`（照片实测）共用同一套归一化坐标约定 `norm_bbox=[x,y,w,h] ∈ [0,1]`，原点左上。
- **并存不破坏**：V2 写入独立库 `data/drawingsv2.db`，不动旧模块表；旧端点退役前用户可见 URL 不变。
- **宁黄勿红**：OCR 疑似误识（MAC→NAC、地暖阀→地暖烟）一律降级为 `LowConfidence`（黄），而非直接判缺标（`Missing`/红）。

## 4. 编排层 · `V2Service.cs · CompareCoreAsync`

一次比对的顺序（也是「匹配并标示」主链路）：

1. **定位档案** → 取 `DrawingMark` 树（图纸侧要求）。
2. **自动选视图** → `BlockMatcher.InferView(photoObs, marks)` 多特征打分；明显领先才自动选，否则回传 `viewCandidates` 供 H5 人工选面。
3. **仿射配准** → `ApplyAffineRegistration`（视图已知时把图纸 view 坐标映射到照片空间）。
4. **锚点配准** → `EstimateAnchorTransform`（文本/QR 贪心最近配对，估尺度 + 平移；残差 `ResidualGate=0.10`，≥3 锚点超阈 → `Suppressed`，`Applied=false` + `needsReview=true`）。
5. **构造 regions** → 把 `NormBbox`（页面坐标）经 `RebaseToView` + 仿射变换成照片空间预期框。
6. **定点感知** → `V2Python.VerifyAsync` 调 Python `verify`（按预期位置裁剪放大，召回高于全图盲检）。
7. **判定** → `MarkVerifier.Verify`（逐 mark 给出九态结论）。
8. **坐标对齐重裁（#27）** → `EstimateConsistentOffset` 取「内容已确认的一致命中项」估系统性整体平移（≥2 项、中位容差 ≤0.25），`ApplyRealignedRegions` 仅「命中才升级 Matched」，离群项保持原判（结构上不可能假绿）。
9. **落库** → `SaveCompare` 写 `data/drawingsv2.db`。

辅助方法：`DistributeCollapsedGroupChildren`（S2 组子项坐标塌陷修复）、`Clamp01`、`FlattenForVerify`。

> 实测固定开销 ≈6.5s/请求：每次 compare 起 2 个 Python 进程（全图盲检 + 定点验证），spawn+imports 单次 ≈1.4s。优化方向（未做）：合并 observe+verify / view 已知跳过盲检 / 常驻进程池。

## 5. 数据模型 · `V2Models.cs`

### 枚举

- **`MarkType`**：`Text` / `Qr` / `Icon` / `Group`（四类应打标对象）。
- **`MarkState`（九态）**：`Matched`(绿) / `Missing`(红,缺标) / `Wrong`(红,内容错) / `Extra`(黄,多标) / `LowConfidence`(黄) / `NotDetected` / `NotApplicable`(灰,非必标) / `NotComparable`(灰,质量不可用) / `ProcessingError`。
  - 四色语义与方案 §8 一致：红=缺标/错标，黄=多标/疑似，绿=一致，灰=跳过/CAD/LCD/icon。
- **`MarkView`（六部位）**：如 `Main` / `Side` / `Back` / `Bottom` 等（图纸多视图布局）。

### `DrawingMark` 关键字段

```csharp
class DrawingMark {
    string Id;
    MarkType Type;
    MarkView View;
    string Text;          // 期望文本（Text 类）
    bool Required;         // 是否必标
    string Condition;      // 条件条款（如「当…时打标」）
    double[] NormBbox;     // 页面坐标归一化 [x,y,w,h]（图纸回显恒用此）
    double[] Bbox;         // 照片空间坐标（裁剪/位置判定/照片画布用）
    double[] ViewBbox;     // 视图坐标（RebaseToView 后）
    double Direction;      // 朝向角
    double Confidence;
    MarkSource Source;     // 来源证据：Kind/PageIndex/RuleId/SpanIds/ImageIds/Evidence
    List<DrawingMark> Children;  // Group 子项
}
```

> ⚠️ 坐标系「按谁用分开」（#10）：`ViewBbox`/变换后坐标是**照片空间**，只给 regions 裁剪/照片画布用；**图纸回显恒用未变换的 `NormBbox` 页面坐标**。同一份坐标给两个画布用＝必然错位（实测 7/7 画错）。

## 6. C# 决策层

### 6.1 建标层 · `MarkBuilder.cs`

`Build(vpdfObs, rules)` → 产出 `DrawingMark` 树，四条证据链：

- **R1 条款声明**：`ExtractDeclared` 解析条款文本（「按键丝印：…」），由 `MarkRules` 的 `ProcessWords`/`DeclarationEndMarkers`/`SplitClauseItems` 切分。
- **R2 已知内容**：`KnownContent`/`Aliases` 直接命中（型号、服务热线等固定内容）。
- **R3 图像对象**：`marks.py` 检出的 QR/图标 → 图纸侧 `images` 落位矩形（用 `get_image_info(xrefs=True)` 拿 bbox，不能只用 `get_images()`）。
- **R4 图面候选兜底**：非条款文本但像打标内容（`IsMarkingLike`）。
- **合并/去重**：R1/R2 同块合并 `EmitGrouped`；`Dedupe` 含「同 view+同 type+IoU≥0.9 + Text 相同」判据（修 p49 `i000`/`i005` 重复 QR）。`InferView` 最近邻视图标签（排除 clause/revision 仅保留 `qrDecl`）。

### 6.2 规则表 · `MarkRules.cs`

21 份图纸实测出的规则，关键集合：

- `ProcessWords` / `DeclarationEndMarkers` / `SplitClauseItems`：条款切分。
- `KnownContent` / `Aliases`：固定内容 + 别名（如型号别称）。
- `QrWords` / `ViewWords`：QR 关键词、视图（部位）关键词。
- `NoiseWords`：含 **油墨/喷码/移印/烫金/丝网印/冷灰/热灰**（刻意**不加「丝印」**，避免误删 p62「按键丝印」这类真实打标内容）。
- `IsNoiseBlock` / `IsMarkingLike` / `IsDimension`（首版曾误判 `MAC` 为尺寸，已修）/ `IsRevisionNote`。

### 6.3 判定层 · `MarkVerifier.cs`（核心 ~1785 行）

**常量**：`PosTol=0.06`、`ViewPosTol=0.10`、`MaxPosTol=0.35`、`IconInkMin=0.02`、`AnchorDistK=0.25`、`OffsetConsistencyTol=0.25`、`MinAlignmentSupport=2`。

**`Verify(photoObs, marks, view)` 流程**：
1. 质量门槛：`NotComparable`（灰）若照片质量不可用。
2. 视图级配准：`RebaseToView`（页面坐标→视图坐标）+ `ViewBboxOf`（视图标签锚点，`maxDist` 默认 1.0）。
3. 逐 mark `VerifyMark`：
   - 非必标 → `NotApplicable`（灰）。
   - 质量不可用 → `NotComparable`（灰）。
   - 按类型分派 `VerifyText` / `VerifyQr` / `VerifyIcon`。

**`VerifyText`**：三级匹配 `Exact` / `Normalized` / `Ambiguous`(黄)；几何未配准时全图盲检兜底 `BlindContentMatch` → `LowConfidence`；OCR 误识容差 `NearestKey`/`NearestKeyOf`（Levenshtein，键长≤6 容差1/更长容差2）命中改判黄。

**`VerifyQr`**：定点解码 → 盲检兜底 → 多 QR 消歧 `ClaimedBlindCodeIdx` → `code_degraded` → `NotComparable`；`QrContentHint`（P4：解码内容仅提示，不影响结论）。

**几何配准**：

- `AnchorTransform`：`ResidualGate=0.10`，超阈 `Suppressed` 抑制（42 例 worse=0，假 Extra 3→0）。
- `EstimateAnchorTransform`：文本/QR 贪心最近配对，≥2 锚点估尺度。
- **#27 坐标对齐**：`OffsetAlignment` / `EstimateConsistentOffset`（≥2 一致偏移取中位数，中位容差 ≤0.25 才重裁）/ `ApplyRealignedRegions`（重裁命中才升级 Matched，未命中保持原判）/ `ReaggregateGroups` / `FindMarkById` / `ParseBlind`。代价：触发时多一次定点调用（42 例 6m55s→8m47s），收益 Matched 64→78、better=14、worse=0。
- 工具：`RebaseToView`/`ViewBboxOf`/`FilterByView`/`UnionBbox`/`PositionOk`（中心距或交叠≥50%）/`RegionObs`/`TextObs`/`BlindCode` 解析。

### 6.4 自动视图识别 · `BlockMatcher.cs · InferView`

`BuildViewSignatures`（从 marks 聚合型号码/QR 预期/文本/质心）+ `ExtractPhotoFeatures`（observe texts/codes）+ `ScoreView`，权重：

| 特征 | 权重 |
|---|---|
| 型号码命中 `WModelCode` | 6.0 |
| QR 解码命中 `WQrDecode` | 5.0 |
| 文本匹配 `WTextMatch` | 2.0 |
| QR 数量 `WQrCount` | 1.5 |
| 布局 `WLayout` | 1.0 |

`Chosen` 须 `Top1 ≥ 1.6×Top2`（`LeadRatio=1.6`）才自动选，否则回传 `viewCandidates` 供 H5 人工选面（`viewInferRate` 94.1→100%）。

> ⚠️ 脆弱点：仅为「盲检 OCR 文本/QR 是否恰好唯一命中某视图 mark」的文本巧合匹配器。真实照片（photo7d）因「服务热线」+「YCWA15NCWQ」跨多视图冲突且 QR 解不出 → 推断为空，**必须人工选面**。最稳方向：用照片检出的型号代码锚定已知视图布局（R1），而非依赖文本巧合。

### 6.5 文字安全归一化 · `TextNormalizer.cs`

- `Normalize`：NFKC + 去空白 + 大写。
- `LooseKey` / `AmbiguousKey`（`O→0`、`I/L→1`、`B→8`、`S→5`、`Z→2`、`G→6`）。
- `Compare`/`Contains` 返回 `TextMatch`：`None`/`Exact`/`Normalized`/`Ambiguous`。
- `0/O·1/I` 只判 `Ambiguous`（黄），**不**直接判绿——防止把「0」误当「O」算一致。

### 6.6 图纸契约入口 · `VectorPdfParser.cs`

`Parse` 校验 `schema=vpdf/1`、页面非空；暴露 `PageSize`。真正解析在 Python `vpdf.reader`。

## 8. 运行时 / 桥接 · `V2Python.cs`

- `RunAsync`：**双向排空 stdout/stderr** 防死锁（MuPDF C 层直写 fd2，`redirect_stderr` 捕获长度 0，必须异步排空）。
- `ExtractJson` 从 stdout 切 JSON（首个 `{` 到最后一个 `}`）—— 因 Python 可能打印额外诊断行，必须以 JSON 行收尾（否则 health 报「未输出 JSON」）。
- 封装：`ParseAsync`（vpdf）/ `ObserveAsync`（全图盲检）/ `VerifyAsync`（定点）/ `RenderDrawingPageAsync`（PNG 二进制读）/ `SelfCheckAsync`。

## 9. Python 感知层

### 9.1 契约

| schema | 产出 | 入口 |
|---|---|---|
| `observe/1` | 照片全图盲观测（质量+几何+OCR+码+subject） | `observe_run.py observe` |
| `observe-verify/1` | 按预期位置定点感知 | `observe_run.py verify --regions` |
| `vpdf/1` | 图纸侧原生对象（span/image/graphics） | `vpdf_run.py parse` |

全部 `norm_bbox=[x,y,w,h] ∈ [0,1]`，原点左上，相对矫正后图像 / 显示空间标准坐标系。

### 9.2 照片侧 `observe/`

- **`pipeline.py · observe_image`**：质量（原图）→ 几何矫正 → OCR(`MAX_SIDE=1280`)+码检测 → `apply_ocr_evidence` → `subject`（内容并集外扩 8%，≥2 元素生效）。
- **`quality.py · assess`**：`SHARPNESS_MIN=100` / `MIN_SIDE=640` / `OVEREXPOSED_RATIO=0.99` / `UNDEREXPOSED_RATIO=0.95` / `DYNAMIC_RANGE_MIN=30`。**`apply_ocr_evidence`**（P-1）：`OCR_CONF_MIN=0.5`，`OVERRIDABLE_REASONS=失焦/灰阶动态范围不足`——OCR 取到内容则清晰度类门槛降级为提示（8 例由拒绝转实判）。
- **`geometry.py`**：`detect_quad`/`warp`/`normalize`；`AREA_MIN_RATIO=0.15` / `AREA_MAX_RATIO=0.99` / `FLAT_CORNER_TOL=0.04` / `ANGLE_TOL_DEG=4.0`；method：`no-quad` / `flat-quad-skip` / `contour-quad`。**平面图纸不做透视矫正**（边框被当四边形→warp 裁页边距致坐标错位 ~4%）。
- **`text.py · detect`**：`rapidocr_onnxruntime` 独立库（非旧 OcrService）；`MIN_CONF=0.50`；`_merge_same_line`（`MERGE_GAP_RATIO=0.012` / `MERGE_DY_RATIO=0.010`，中英混排 `_needs_no_space` 不加空格）；OCR 框轻度外扩 6% 防差之毫厘。只报「看到什么」，不判对错。
- **`marks.py · detect`**：四级 QR 降级 `pyzbar → zxing-cpp → cv2 QR → contour-square`；`_cv2_qr_tiled` 分块扫小码；degraded 时上层判 `NotComparable`。
- **`verify.py · verify_image`**：定点感知；`QR_SCALES=(1,2,4)`、`TEXT_MAX_SIDE=1280`、`BLANK_SKIP` 默认关；`_verify_qr`(cv2-qr/pyzbar/zxing-cpp + ink_ratio 辅助) / `_verify_text`(白边+尺寸限制+坐标映射回 crop) / `_presence`。
- **`observe_run.py`**：薄壳入口（计划任务下 `python -m` 不可靠）；`--json-only` 让 stdout 只吐纯 JSON。

> RapidOCR 小裁剪失灵坑：极端长宽比文本条带 0 检出，四周加白边 ≥64px 立即恢复（DB 检测需要上下文）。

### 9.3 图纸侧 `vpdf/`

- **`reader.py · read_pdf/read_page`**：`fitz` 读取；先 `page.remove_rotation()` 再取 `page.rect` 作标准坐标系；`MIN_WORDS_FOR_TEXT_LAYER=20`（19/21 份有原生文字层，2 份转曲件走视觉兜底）。`_text_spans`（原生字符层，带 font/size/dir/angle/color）、`_images`（`get_image_info(xrefs=True)` 拿 bbox）、`_graphics`（默认不调用，占解析耗时 82%）。`sha256_file` 内容寻址。`_silence_mupdf` 静音 Ink 批注噪声（数据无影响，但 C# 必须异步排空 stderr）。
- **`normalize.py`**：坐标系归一化。**2026-09-11 修正**：首版假设「page.rect 宽高即 bbox 坐标系」并强制横版旋转，实测错误（PyMuPDF 的 `get_*` 坐标位于未旋转原始空间，须 `remove_rotation()` 后才落入显示空间）。现以「显示空间标准坐标系」为准，**不强制横向**（2 份 10 寸屏是真实竖版）。`clamp_rect`（字体 ascent 溢出裁剪，实测 x1=844.58>842）、`norm_bbox`/`denorm_rect`、`angle_from_dir`（`remove_rotation` 后调，否则全页假角度）。
- **`cli.py`**：`parse` / `sweep` / `verify`（坐标合法性验收闸，`M1` 回归门禁——曾因猜旋转致 `norm_bbox` 越界 `y0=1.22`）/ `selfcheck`（归一化数学自检，以 JSON 行收尾）/ `render`（PDF 页→PNG 二进制，供 H5 回显，DPI 150）。
- **`vpdf_run.py`**：图纸侧桥接入口（与 `observe_run.py` 同套路）。
