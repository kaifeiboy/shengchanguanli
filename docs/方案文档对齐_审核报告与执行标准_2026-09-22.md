## 3. 新执行标准（今后所有 v2 改动必须遵守）

### 3.1 对齐原则（硬规则）

1. **方案文档是唯一基准。** 代码与方案冲突时改代码，不得改方案文档迁就现状。
2. **例外必须登记。** 若某条已被实测推翻（如 `LooseKey` 去标点、第九态 `NotDetected`、OCR 证据豁免清晰度门槛），须在本文档「例外登记」章节写明实测证据并获用户拍板，否则一律按方案改。
3. **事实驱动，双角度验证。** 任何根因判定须 ≥2 个独立角度交叉一致（端点真实输出 / DB 底层 / Python 独立复现 / 算法层直测 / 渲染裁剪 OCR）；验证必须走真实入口（`/api/drawingsv2/compare/upload`），截图与口头描述不能单独作为依据。
4. **每次改动的固定流程：** 备份 → 改代码 → 编译 → 真实端点实测 → 基线回归 → 写记录。改 C# 后才需 `Stop → build → Start`；改 `wwwroot/index.html` 刷新即生效。

### 3.2 冻结边界

- **不得触碰平台共享面**：`Program.cs`、`OcrService`、`Core/**`、`MODULE_RENDERERS`、`subs`、其它模块、`Platform.csproj`。
- v2 改动范围限定：`src/Platform/Modules/DrawingsV2/**`、`src/Platform/wwwroot/index.html` 的 v2 段落、新增 `v2_*` 表、本模块 `Scripts/**`。
- 验证工程一律放 `tools/DrawingsV2_Validation/`（不得放模块目录内，否则被 SDK 默认 glob 卷进主工程）。

### 3.3 验收门槛（量化，全部满足才算完成）

| 指标 | 门槛 | 当前 |
|---|---|---|
| 图纸侧真实打标内容召回 | ≥ 90% | **20%** |
| 自动视图/部位识别准确率 | ≥ 95% | 未达（真实照片常推断为空） |
| 实物照片 OCR 召回 | ≥ 95% | 未达（JQ 面板 warp 下 0） |
| 假红率（误判缺标） | ≤ 5% | 未基线化 |
| 高置信判定占比 | ≥ 90% | 未基线化 |
| 回归 42 例 | `worse = 0` | 需每阶段重跑 |
| 端点 P95 耗时 | ≤ 8s | ~6.5s 固定开销 + OCR |

### 3.4 回归基线机制

- 基线脚本：`Scripts/eval/run_baseline.py --require-truth`（无真值不产出结论）。
- 每阶段结束必须重跑基线并与上一版对比，`worse > 0` 一律回退。
- 新代码解析出的档案需**重分析**才生效（会被置 `draft`），重分析属数据变更，须先拍板。
