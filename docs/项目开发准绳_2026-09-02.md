## 1. 项目定位与目标

**生产管理平台**：.NET 8 Minimal API + SQLite + H5 手机端（浅色商务风），Python 承担 OCR/图像处理。插件式 `IModule`，H5 用 `MODULE_RENDERERS` + `subs` 按 key 渲染。

**核心业务（drawings 打标首件对比）**：
把 CAD 图纸切成块 → 提取每块的「文本 + 图标」→ 与现场实拍照片的真实打标内容逐字比对 → 在照片上用四色框标出差异。

**一句话目标**：让质检员拍一张产品照片，就能自动判断打标内容是否缺标/错标/多标，且**规则对所有图纸通用，不做单一产品补丁**。

1. **不得更改平台和其它模块代码及设置**；与其它模块共用的代码/功能，不得做影响其它模块的修改。改前必须 `grep` 查调用方与共享面。

3. **维护模式**：只改被明确要求的部分 → 界定影响面 → 只改必要 → 跑本模块冒烟+回归 → 动模块外先问。

### 3.2 事实验证准则（2026-08-18 用户确立）

- 所有回答必须基于事实验证，有充分依据才判断。
- **根因修复须 ≥2 个独立角度验证同时成立**（C# 端点输出 / DB 数据 / Python 独立复现 / 算法直测 / monkey-patch 链路，取 ≥2 交叉一致）。
- 截图、口头描述**不可单独**作为根因依据。依据冲突时，以**代码级复现**为权威。

### 3.3 测试真实性准则（2026-08-19 用户确立，五条）

1. **入口链确认先行**：改代码前先查 H5 实际调用的端点（index.html 的 fetch URL）→ 查 C# 该端点实际调用的 Python 模式/参数。
   - ⚠️ H5 主入口是 **`match-and-photo`**（→ C# `MatchAndPhoto` → **`run()` 单块模式 8 参数**）。
   - `diff-photo` 端点（→ `run_on_photo` photo 模式 6 参数）**只是回滚通道**。**测错端点 = 测的不是用户看到的。**
2. **进程缓存**：C# 长驻进程 / `ocr_worker` 会 import 缓存 .py，**必须重启 Platform 才生效**；subprocess 每次新进程加载最新。两者结论必须一致才算数。
3. **输入数据追溯**：以服务端保存的输入照片副本（`data/seg/<did>/match_*.jpg`，文件名=上传文件 md5）为权威，勿用本地缓存照片假设。历史快照（`drawing_histories.SnapshotPath`）是旧引擎结果，不代表当前引擎。
4. **定量优先**：像素扫描（numpy）> 肉眼看图。看图仅作参考，且需与扫描交叉。
5. **每轮验证清单**：真实端点 JSON / C# 调用链代码实读 / Python 同参数独立复现 / 像素扫描定量 / DB 底层数据，**取 ≥2 交叉**；任一不一致立即追查。

### 3.4 进程加载校验（每次验证前必做）

长驻 `ocr_worker` 缓存 import 的 .py。**真实端点验证前必须确认 Platform 进程 StartTime > 所改 .py 的 mtime**，否则验证的是旧代码、结论不可信。

### 3.5 修复提交规则（2026-08-22 用户拍板）

- 任何标示/匹配逻辑修复，**必须先在真实链路（match-and-photo 真实端点 + 重启 Platform 后）做真实环境测试，交叉 ≥2 角度确认成功，才可提交用户复核**。
- 禁止未验证即提交。修复方案有多个候选时，**必须全部执行并逐一验证**。
- ⚠️ **关键认知**：JSON 的 `greenRegions` 是文本**完整 bbox**，绘制时才在图标/QR 处断开。所以"压 QR/压图标"的判定**必须看 diff 图像素扫描**（真绿 = 绿通道显著高于红蓝 >45 且 >120），**不能看 JSON 坐标**。

## 4. 业务规格：四色标示规则（全图纸通用，2026-08-19/20 用户拍板）

| 状态 | 含义 | 照片上标示 |
|---|---|---|
| 🟢 绿框 | 文本匹配正确（照片有、块有、内容一致） | 整行绿框 |
| 🟢+🔴 | 文本个别字符不一致（其余相同） | **绿框 + 错误字符红框**（绿框内标红） |
| 🔴 红框 | 文本完全不同 / 块有照片无（缺标/错标） | 红框 |
| 🟡 黄框 | **仅图标类**（含 QR/NFC/logo）：任一方没有 | 黄框，只做**存在性**对比 |
| ⚪ gray | 块中舍弃位（CAD 标注/说明性文字） | **仅块侧虚标，照片不标** |
| ⬜ low_conf | 照片未拍到该块 | 不画任何框 |

**关键区分（务必记牢）**：
- 图标（含 QR、NFC、logo）**只做存在性对比**（有没有），**不做内容/位置精确匹配**。QR **不识别内容**。
- 文本做**内容匹配**：一致绿、缺标红。**"不同文本"（照片有、块无）不标示。**
- **序列号/批次码的自动灰化已废除**（v19.1 规则作废），与正常文本一致逐字对比：正确位绿、不同位红。
- **标示只做文本级一层**，禁止块级 ROI 外框（v19.48）。
- **所有框在 QR/图标投影处断开**，不压 QR、不压图标。
- **标示去重**：同位置同色只画一次（IoU≥0.6），不叠加。
- 型号/多视图：照片型号行只归属同型号块；型号修正**仅少量图纸中有，不做大范围适用**。
