## 0. 差异等级说明

- **✓ 已实现**：方案要求与代码行为一致。
- **部分实现**：核心意图满足，但方案某些细节点未落地。
- **背离**：代码行为明确违反方案明文要求（含"功能越界"与"刻意放弃"两类）。
- **未实现**：方案要求项在代码中完全缺失，属尚未覆盖的增强范围。

## 2. §4 图块生成

**方案要求**
- 以产品视图或打标区域为单位生成图块，每个图块保存：完整局部图、打标对象透明层、视图名称、基准点、比例、方向、对象列表。
- 图块记录：固定文字集合、二维码数量、图标数量、对象相对位置、视图长宽比、产品轮廓等特征。
- 照片上传后先按这些特征选候选图块再详细匹配，不与该型号所有图块逐一高成本比对。

**当前实现**
- 无独立"图块"子图实体。视图 = `v2_drawing_views`（当前每档案 1 页），标位 = `v2_drawing_marks`，比对直接在整页标位上做。
- 检索 `transparen|透明层|图块|tile|比例|方向(实体)` 在 DrawingsV2 内无对应实现（仅有"自动找图块"注释）。
- "按特征候选筛选"已实现：`BlockMatcher.cs:8` 注释明确"特征级找图块（设计 §5·Phase2 / 偏差 B1+B3）"，按型号码(6.0)/QR(5.0)/文本(2.0)/布局(1.0) 多特征加权打分取 Top-N，避免全量比对。

**差异判定**：部分实现（候选筛选✓，图块实体✗）。

**证据**
- `src/Platform/Modules/DrawingsV2/Decision/BlockMatcher.cs:8` — 特征级找图块注释
- `src/Platform/Modules/DrawingsV2/Runtime/V2Service.cs:320` — `MarkView? inferredView`（自动找图块）

## 3. §5 照片处理和图块匹配

**方案要求**
- 质量检查：清晰度、亮度、主体大小、遮挡程度、目标区域是否完整；不满足返回"请重新拍摄"，**不直接判定缺标**。
- 通过后检测文字/二维码/图标/产品轮廓，执行旋转校正、透视校正、尺度归一化。
- 平面 PVC 盖子优先使用**边框、孔位、面板轮廓或其他稳定结构作为基准点**；无法找到足够基准点时降低匹配置信度并要求人工复核。
- 两步匹配：① 找图块（按特征选候选，多候选接近时 H5 让用户选部位）；② 验标（图块内每个对象与照片对象一对一，文字逐字比，QR/图标只比存在性与位置，保留对象级明细）。

**当前实现**
- 质量检查：`quality.py` 含失焦/动态范围/分辨率/过曝/过暗；P5(#27) 改为"OCR 成功时失焦/动态范围由阻断降级为提示、不判缺标"，满足方案"不直接判缺标"；但分辨率/过曝/过暗仍硬阻断（`usable=0`）。
- 旋转/透视/尺度：仅在检测到 QR 锚点时做仿射（`V2Service.cs:328 geometryApplied=透视矫正`）；记录 #688（Nameplate 面、无 QR）实测 `geometryMethod=no-quad`、`geometryApplied=false`、`alignment=null` —— 不配准。
- **基准点（轮廓/孔位/面板）**：`MarkVerifier.cs:143-144` 注释明确记载——"最初设计 Stage2 的『轮廓→边框/孔位/面板结构』经实测不可行：图纸侧 `v2_drawing_views` 无几何字段；照片侧 3 张真实照片合格基准点候选 0/3"。代码内 `subject`（产品轮廓）默认 `null`（`MarkVerifier.cs:93,104`）。属**刻意放弃**。
- 两步匹配 + 多候选用户选：已实现。

**差异判定**：显著背离（基准点方案被代码注释记为不可行已放弃）；几何/质检部分实现。

**证据**
- `src/Platform/Modules/DrawingsV2/Decision/MarkVerifier.cs:93,104,143-144` — 轮廓/基准点放弃的注释与 `subject` 默认 null
- `src/Platform/Modules/DrawingsV2/Runtime/V2Service.cs:328` — `geometryApplied=透视矫正`
- DB 记录 #688：`geometryMethod=no-quad, geometryApplied=false, alignment=null`
- `Scripts/observe/quality.py` — `apply_ocr_evidence()` OCR 前置降级逻辑（P5 #27）

## 4. §6 文字匹配规则

**方案要求**
- 安全归一化：全角半角统一、大小写统一、首尾空格清理、连续空格合并；数字/字母/斜杠/连字符/加减号/直径符号/单位不随意替换。
- `0/O`、`1/I` 等易混淆字符记录为低置信度，不直接视为相同。
- 固定文字逐字一致；**可变化文字（日期/批次/流水号）保存格式规则，只校验长度、字符范围、格式，不要求与图纸示例完全相同**。
- 匹配结果保存正确字符区间、错误字符区间、缺失区间、多余区间，渲染时只标示对应区段。
- 照片侧识别必须保存**字符坐标和置信度**，不能只存整段字符串；置信度过低或区域被遮挡时返回待复核，不直接返回缺标。

**当前实现**
- 安全归一化 + `0/O`·`1/I` 低置信：已实现（`MarkVerifier.NearestKey` Levenshtein 容差命中→`low_confidence`）。
- **可变文字格式规则**：`condition_text` 仅为存储字段（`V2Store.cs:145` 列定义）；`MarkRules.cs:247` 将"流水号/生产日期"等列入**噪声丢弃清单**，并无"按格式校验长度/范围"的通用校验器 → 未实现。
- **字符级坐标与区间标示**：`verdicts_json`（记录 #688）仅含 `photoBbox/drawingBbox/expectedBbox` 对象级框，无 correct/wrong/missing/extra 字符区间；`MarkBuilder.cs` 的 `spans` 是**图纸侧 PDF 文本 span**（建标用），非照片侧字符级 mismatch 区间 → 未实现。
- 低置信/待复核状态存在（`low_confidence` / `not_comparable`）。

**差异判定**：部分实现（归一化/易混字符✓；可变文字格式、字符级坐标与区间未实现）。

**证据**
- `src/Platform/Modules/DrawingsV2/Decision/V2Store.cs:145` — `condition_text TEXT NULL`
- `src/Platform/Modules/DrawingsV2/Decision/MarkRules.cs:247` — 噪声词含"流水号/生产日期"（丢弃，非格式校验）
- `src/Platform/Modules/DrawingsV2/Decision/MarkBuilder.cs:322-362` — `spans` 为图纸侧 PDF span
- DB 记录 #688 `verdicts_json` — 仅对象级 bbox，无字符区间

## 5. §7 二维码和图标匹配规则

**方案要求（关键句）**
- "**二维码不读取具体编码内容**，只检测照片中是否存在二维码、二维码外接矩形、方向和中心位置"。
- 图标同规则：只比较存在性、类别是否大致一致、位置是否对应。
- 图纸照片都有且位置误差允许→不绘色；一侧有→黄；位置明显偏移→黄+人工复核。
- "二维码内容不同不影响通过结果"。

**当前实现**
- QR **实际被解码并用于身份锚定**：`BlockMatcher.cs:29 WQrDecode=5.0`、`QrExpected.Contains(Clean(qd))` 用解码内容命中视图；DB 记录 #688 实测 `code_detector=pyzbar`、`code_degraded=0`（真解码）；`MarkVerifier.VerifyQr`（#27 P4）用 QR 内容做 §7 回正与消歧。
- 存在性/位置比较、`extra`/`missing`/偏移→黄、`ResidualGate` 残差门控触发 `needsReview` ✓；P4 已落实"内容不同不影响通过"（内容不判黄）。

**差异判定**：功能越界（背离方案"不读取内容"）。当前因 P4 守住了"内容不影响通过"，功能未出错，但已超出方案功能边界，且方案未同步修订。

**证据**
- `src/Platform/Modules/DrawingsV2/Decision/BlockMatcher.cs:29,194-196` — `WQrDecode` 与 `QrExpected.Contains(Clean(qd))`
- DB 记录 #688：`code_detector=pyzbar, code_degraded=0`
- `src/Platform/Modules/DrawingsV2/Decision/MarkVerifier.cs` — `VerifyQr`（§7 回正、`QrContentHint`、`ClaimedBlindCodeIdx`）

## 6. §8 结果标示规则

**方案要求**
- 绿=已找到且一致（文字逐字一致或 QR/图标存在且位置正确）。
- 红=图纸要求文字缺失、文字错误或明确位置错误。
- 黄=QR/图标一侧存在一侧不存在、位置偏差大、照片质量不足、识别置信度不足。
- 灰=不适用、未拍到该部位、当前无法比较（不代表合格）。
- 照片标示与图纸块标示使用同一对象状态。
- 枚举：`matched` / `missing` / `wrong` / `extra` / `low_confidence` / `not_applicable` / `not_comparable` / `processing_error`。
- 汇总：存在红→不通过；无红有黄→待复核；全部必检对象绿→通过。

**当前实现**
- 四色映射、枚举、灰≠合格、照片/图纸共用状态，均与 `verdicts_json` 状态机一致。
- 汇总逻辑（不通过/待复核/通过）由 H5 按 `counts_json` 驱动；`required` 字段已存（必检判断可用）。

**差异判定**：已实现（落地最完整的一章）。

**证据**
- DB 记录 #688 `counts_json={"NotApplicable":1,"selected_view":"Nameplate"}`、`verdicts_json` 状态枚举
- `v2_drawing_marks.required` 列用于必检判定

## 7. 结论与建议

1. **最应处理的两条背离**
   - **§7 二维码读内容**：目前被正向利用（型号码锚定视图、QR 锚点仿射），且 P4 已保"内容不影响通过"，功能无碍，但**与方案明文冲突**。建议二选一：① 保持现状，但把方案 §7 修订为"可读内容用于辅助锚定"；② 回到方案纯洁，仅用 QR 存在性/位置，视图锚定改用其它稳定信号。
   - **§5 基准点方案**：已被代码注释记为"实测不可行已放弃"，属有证据的刻意决策，但方案文档未同步修订，建议回填 §5 并标注替代方案（QR 锚点仿射 + `#27` 一致偏移重裁）。

2. **§4 / §6 属"范围未覆盖"而非"做错"**：图块实体、可变文字格式、字符级区间在当前 v2 完全未做，是尚未实现的增强项，不影响现有比对正确性，可排期补齐。

3. **§8 已完整落地**，标示语义与枚举和方案一致。

4. **待办（供排期）**
   - [ ] 修订方案 §5（基准点放弃 + 替代方案）与 §7（QR 内容用途口径）
   - [ ] 评估去掉 QR 解码仅用存在性对 #63/#66 等档案视图识别准确率的影响（用 42 例基线实测）
   - [ ] 排期：图块透明层实体、可变文字格式校验器、字符级区间标示
