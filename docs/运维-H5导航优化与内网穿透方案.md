## 一、任务一：H5 界面操作逻辑优化（移动端习惯）

### 1.1 现状问题（根因）

H5（`src/Platform/wwwroot/index.html`）所有页面切换均用 `innerHTML` 直接替换 `#moduleRoot`，**全程未调用 `history.pushState`**，浏览器历史栈始终为空。后果：手机系统返回键无历史可退 → 直接退出到浏览器首页，而非返回上一操作页。

涉及入口（已全量盘点）：
- 页面级视图 9 个：`openCompare / openDetail / openHistoryView`（drawings）、`dhPageQuery / dhPageAdd / dhPageBatch / dhPageExport / dhPageAnalysis`（defecthistory）
- 弹层 6 类：`openSheet / openDrawer / openToolSheet / openScan`（含遮罩与关闭按钮）

### 1.2 方案：轻量历史栈管理器

注入约 6 行基础设施 + 散点接入，模型为"每帧 = 当前页按返回键时该执行什么"：
- `navPush(backFn)`：进入子页/弹层时入栈 + `history.pushState`
- `popstate` 监听：返回键触发时弹栈执行 backFn → 回到上一页
- `navBack()`：返回按钮/关闭按钮统一调 `history.back()`，与物理返回键走同一路径
- `activateModule` 切模块时清栈（重置导航起点）

弹层内部多级（drawer 的 usage/addr/about、toolSheet 的 addPanel）不接栈，避免嵌套混乱；弹层整体作为一个栈帧，返回键关弹层。

### 1.3 改动清单（共 ~22 处，纯 JS）

| 类别 | 接入点 | 改动 |
|------|--------|------|
| 基础设施 | `const $` 前 | 新增 `_navBacks/navPush/navBack/popstate` 监听 |
| 模块切换 | `activateModule` 开头 | `_navBacks.length=0` 清栈 |
| drawings 页面级 ×3 | openCompare/openDetail/openHistoryView | `navPush(renderDrawingsModule)` + 返回按钮 `→navBack` |
| defecthistory 页面级 ×5 | dhPageQuery/Add/Batch/Export/Analysis | `navPush(dhRenderMenu)` + dhBack `→navBack` |
| 弹层 open ×4 | openSheet/openDrawer/openToolSheet/openScan | `navPush(close弹层)` |
| 弹层关闭按钮/遮罩 ×7 | sheetClose/overlay/menuClose/menuOverlay/toolClose/toolOverlay/scanClose | `→navBack` |

**未触碰**：CSS 视觉风格、后端 C#/Python、API 契约、端口、Program.cs。

### 1.4 影响评估

- **风险：低**。仅改 index.html 的 JS 导航逻辑，wwwroot 为静态文件，浏览器刷新即生效，**Kestrel 无需重启、平台持续运行**。
- 已通过 node `vm.Script` 语法编译检查（1 个 inline script 通过）。
- 已 grep 验证：0 处旧 `onclick=renderDrawingsModule/dhRenderMenu/close*` 残留，全部改为 `navBack`。

### 1.5 验证与回滚

- 验证：手机端逐级测试——模块菜单 → 子页 → 返回键回菜单；弹层 → 返回键关弹层。
- 回滚：备份 `src/Platform/wwwroot/index.html.bak_nav_20260810`，可直接覆盖还原。

## 二、任务二：内网穿透方案重做

### 2.1 现状问题

当前 `start-platform.ps1` 启动 cloudflared **quick tunnel**（`--url http://127.0.0.1:5000`），存在两个硬伤：
1. URL 为随机 `https://xxxx.trycloudflare.com`，**每次重启都变** → 不满足"地址重启不变"。
2. 2026-07-09 起国内 4G 访问报 Error 1033（QUIC/边缘路由问题），**外网实际不可用**。

### 2.2 方案选型过程（关键纠错）

用户约束：免费 + 固定地址 + 重启不变 + 同一地址自动识别内外网。

| 方案 | 免费 | 固定地址 | 国内4G | 结论 |
|------|------|----------|--------|------|
| cloudflared quick tunnel（现状） | ✓ | ✗ 随机变 | ✗ 1033 | 弃 |
| cpolar 免费版 | ✓ | ✗ 随机+24h过期 | ✓ | **弃**（核实官网：免费版随机临时域名，固定需付费基础版起） |
| natapp 免费隧道 | ✓ | ✓（authtoken 绑定） | ✓ 国内服务器 | **选** |
| Cloudflare named tunnel | 隧道✓ | ✓ | ⚠ 需实测1033 | 备选（需自有域名，非纯免费） |

**纠错说明**：初选 cpolar 免费版，但核实 cpolar 官网价格页发现**免费版是随机临时域名 + 24 小时过期需续期**，不满足"重启不变"。改为 natapp 免费隧道：注册领取的 authtoken 固定 → 对应公网域名固定、重启不变；本地端口可指定 5000；1Mbps 对低频文字查询够用。

> **域名固定性已确认**：natapp 官方教程机制为「购买隧道获得 authtoken → authtoken 固定 → 对应隧道与公网域名固定」，重启 natapp 客户端连接同一条隧道，域名不变（区别于 cpolar 免费版的随机临时域名）。免费版为 **http** 域名（如 `xxx.natappfree.cc`），https 需 VIP。首次领取后仍建议重启一次实测确认。

### 2.3 natapp 部署步骤（一次性）

1. 注册认证：https://natapp.cn 注册 + 实名认证。
2. 领取免费隧道：用户后台 → 购买隧道 → 免费 Web 隧道，**本地端口填 5000**，本地地址 127.0.0.1。
3. 复制 authtoken：隧道管理页复制该隧道 authtoken，写入 `data/natapp_token.txt`（单行无空格）。
4. 下载客户端（二选一）：
   - **官方自动安装（推荐）**：在任意空目录终端执行 `powershell -c "irm https://natapp.cn/get.ps1?authtoken=你的TOKEN | iex"`，自动下载 natapp.exe 并生成 run_natapp.bat。
   - 手动：https://natapp.cn/download 选 Windows 64 位，解压 `natapp.exe` 放到 `natapp/` 子目录（与 start-tunnel-natapp.bat 同级）。
5. 记录固定域名：隧道页显示的公网域名（如 `xxx.natapp1.cc`），填入 `src/Platform/appsettings.json` 的 `External:BaseUrl`（见 2.5）。
6. 启动：双击 `start-tunnel-natapp.bat`，控制台显示 Tunnel Status Online + 公网域名即成功。

### 2.4 启动脚本

已新建 `start-tunnel-natapp.bat`：
- 读 `data/natapp_token.txt` 获取 authtoken
- 调用 `natapp/natapp.exe -authtoken=TOKEN -log=stdout`
- 前置检查：token 未配 / natapp.exe 不存在时给出明确提示并退出

**未改 `start-platform.ps1`**（其仍含 cloudflared quick tunnel 段，作为内网备用/回退），避免影响平台构建与启动流程。natapp 作为独立隧道进程运行，开机自启可新建计划任务调用本 bat。

### 2.5 后端配置注入（无需改代码）

后端 `Program.cs:84-92` 已内置固定地址注入：
```
External:BaseUrl 配置项 → 若空则回退读 data/tunnel_url.txt
```
把 natapp 固定域名填入 `src/Platform/appsettings.json`：
```json
"External": { "BaseUrl": "https://xxx.natapp1.cc" }
```
重启平台后 `api/network/info` 即返回该固定外网地址。**不改后端代码**。

### 2.6 内外网自动引导（前端已实现）

已注入 H5 启动处（`loadNet()` 后）：
- 基于 `location.hostname` 识别内外网（内网 IP 段：127./localhost/192.168./10./172.16-31）——可靠，不依赖跨协议网络探测（https 外网页面探测 http 内网会被混合内容拦截）。
- 外网访问时：调 `api/network/info` 拿内网 `internalBaseUrl`，顶部显示浅绿引导条"当前为外网访问，检测到本机内网地址可更快访问 [切换内网] [×]"。
- 点"切换内网" → `location.replace` 到内网地址（导航不受混合内容限制）。
- 内网访问时不显示引导条。

### 2.7 退路（若 1Mbps 不够 / 需 https / natapp 不稳）

- **natapp VIP_1 型**：¥9/月，固定二级域名 + 自定义本地端口 + 更高带宽 + https 支持。
- **Cloudflare named tunnel**：需一个域名（约¥几十/年）托管 Cloudflare，隧道免费不限速、自带 https，本机已有 cloudflared.exe；但需先验证国内 4G 的 Error 1033 是否已消除。
- 若仅需 https 且愿用域名：Cloudflare named tunnel 是更优长期方案。
