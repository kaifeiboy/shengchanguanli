# 打标首件对比模块 · 维护升级规则（每次维护升级必执行）

> **适用范围**：仅「打标首件对比」模块（`drawings`）。本规则为硬约束，任何改动前先读、改动后必查。
> **制定依据**：用户 2026-08-27 指令——升级维护不得影响平台及其它模块的正常运行，修复升级改动后需真实环境自检是否符合当前规则和修复内容是否符合要求才提交审核。

## 一、核心原则

### 1.1 范围隔离原则
- **可改动文件**（仅本模块）：
  - `src/Platform/Modules/Drawings/` 目录下的所有文件
  - `src/Platform/wwwroot/index.html` 中 `renderDrawingsModule` 及 `drawings*` 系列函数

- **严禁改动**（共享/平台面）：
  - `Program.cs`、平台启动脚本、`platform-watchdog.js`、端口与 Kestrel 配置
  - `Modules/DefectHistory/**`、`Modules/Unbind/**`、`Modules/PackagingInspection/**`
  - `Core/**`、`Infrastructure/**`
  - `index.html` 中其他模块的渲染器、`MODULE_RENDERERS`、`subs` 映射

### 1.2 依赖保护原则
- **共享服务依赖**：
  - `OcrService` 被 `Unbind` 和 `DefectHistory` 模块共享
  - 修改 `OcrService` 前必须 `grep` 引用确认不影响其他模块
  - 如需修改其签名/行为 → 视为影响其它模块，必须与用户确认

### 1.3 真实环境自检原则
**真实运行实例**：Kestrel `http://127.0.0.1:5000`（生产），`Platform.exe` 由 SYSTEM 计划任务 `SCG_Platform` 托管。

#### 改动类型 → 生效方式
| 改动 | 生效方式 | 是否需重建 |
|---|---|---|
| 仅 Python 文件（`*.py`） | 子进程每次调用加载最新，即时生效 | 否 |
| 仅 `index.html`（前端） | 静态文件，下次请求即生效（浏览器可能缓存） | 否 |
| C# 文件（`*.cs`） | 需重建并重启服务 | 是 |

#### 真实环境自检清单（缺一项不得提交）
1. **平台存活验证**：
   - `curl http://127.0.0.1:5000/` → 首页可加载
   - `curl http://127.0.0.1:5000/api/modules` → 模块列表正常
   - `curl http://127.0.0.1:5000/api/drawings/` → drawings 模块响应正常

2. **其他模块不受影响验证**：
   - `curl http://127.0.0.1:5000/api/unbind/...` → unbind 模端点正常
   - `curl http://127.0.0.1:5000/api/defecthistory/...` → defecthistory 模块端点正常
   - 端口 5000 监听正常，无新增异常日志

3. **Drawings 模块功能验证**：
   - **匹配功能**：上传测试照片做匹配 → 返回正确的匹配结果
   - **标示功能**：测试 `/diff-photo` 端点 → 标示结果符合预期
   - **历史记录**：`/api/drawings/history` 端点正常返回

4. **护栏验证**：
   - 运行 `validate.py` → 基线零漂移
   - 运行 `real_match_regression.py` → 全图纸绿/黄/灰零回归

### 1.4 C# 重建与重启规范（如改动 C#）
1. `Stop-ScheduledTask SCG_Platform`（PowerShell，SYSTEM 任务）
2. `dotnet build -c Debug`（本机 SDK `C:\Program Files\dotnet\dotnet.exe`）
3. `Start-ScheduledTask SCG_Platform`
4. **进程加载校验**：确认 `Platform.exe` 启动时间晚于所改 `.cs`/`.py` 文件的 mtime

## 二、当前模块架构分析

### 2.1 核心文件清单（生产必需）
#### C# 核心文件（不可删除）
- `DrawingModule.cs` - 模块注册和端点映射
- `DrawingService.cs` - 核心业务逻辑
- `OcrService.cs` - OCR 服务（共享依赖，修改需谨慎）
- `ModelParser.cs` - 型号解析工具

#### Python 核心文件（不可删除）
- `diff_visualizer.py` - 匹配引擎核心，四色标示体系
- `photo_registration.py` - ROI 定位，照片 OCR
- `ocr_worker.py` - 常驻 OCR 工作进程
- `ocr_cli.py` - 单图 OCR 脚本
- `batch_ocr.py` - 批量 OCR 脚本
- `segment_blocks.py` - 图纸切割为小图块
- `geo_score.py` - SIFT+RANSAC 几何辅助打分
- `validate.py` - 护栏：全量回归门禁
- `real_match_regression.py` - 全量动态回归
- `fleet_sweep.py` - 静态扫描

### 2.2 辅助文件（可考虑归档）
#### 诊断和演示文件（建议归档到 `_archived_diagnostics/`）
- `_diag_*.py` 系列文件 - 诊断脚本
- `_demo_*.py` 系列文件 - 演示脚本
- `diag_*.py` 系列文件 - 诊断工具
- `diagnose_diffs.py` - 差异诊断
- `demo_*.py` 系列文件 - 演示工具

#### 临时文件（可删除）
- `temp_*.py` 系列文件 - 临时探测脚本
- `*.tmp` 文件 - 临时文件（当前有4个）
- `err.txt`, `hsxc_err.txt` - 空错误日志文件
- `validate_baseline.out` - 验证基线输出
- `verify_*.out` - 验证输出文件

#### 备份文件（可删除）
- `diff_visualizer.py.orig_bak` - 原始备份

#### 文档文件（可移至 docs/）
- `impact_analysis_lcd_display.md` - LCD 屏显影响分析
- `plan_lcd_display_region.md` - LCD 屏显区域计划

### 3.2 代码优化建议（优先级：中）

#### 3.2.1 冗余计算识别
1. **OCR 重复调用**：
   - `diff_visualizer.py` 和 `photo_registration.py` 都调用 OCR
   - 建议：统一通过 `ocr_worker.py` 或增加缓存机制

2. **重复的文本匹配逻辑**：
   - `_texts_match_strict` 和 `_norm_text` 在多个文件中重复
   - 建议：抽取为公共工具模块

#### 3.2.2 性能优化机会
1. **缓存优化**：
   - `DrawingService.cs` 已有缓存机制，但可考虑增加更多缓存层级
   - 块 OCR 结果可缓存，避免重复计算

2. **并行处理**：
   - 批量 OCR 可考虑并行处理
   - 多块匹配可并行计算

### 3.3 代码质量改进建议（优先级：低）
1. **错误处理统一**：
   - Python 脚本的错误处理方式不统一
   - 建议统一异常处理和日志记录

2. **配置管理**：
   - 硬编码的路径和参数建议移至配置文件
   - 阈值参数建议可配置化
