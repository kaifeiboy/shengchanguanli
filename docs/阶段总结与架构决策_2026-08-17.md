## 3. 最优实现路径记录（关键技术决策沉淀）

> 本节记录**被实践证明正确、应长期保留**的路径，以及**已被放弃 / 需规避**的歧路。

### 3.1 匹配范式重建（核心范式决策）⭐⭐⭐

**最优路径**（`diff_visualizer.py` 的 `run()` / `run_on_photo()`）：
1. **同源实时 OCR**：照片与块图都走同一 live RapidOCR；DB RawText 降级为"补充/参考"，不再作唯一基准。→ 根除"两侧文本不同源"与"DB 脏数据污染匹配"。
2. **照片 ROI 位置感知**：检测标签牌矩形区域 / 块在照片的 ROI，按位置比对，消除跨块溢出假多标（`_has_label_feature` 启发式随之退休）。
3. **四色框语义体系**：红=缺/多标、黄=多标、绿=一致、灰=尺寸·CJK垃圾·QR噪声·图标重叠；`silentSkipped`=不画框。

**已弃用路径**：在"文字袋 + 全局 OCR + 占位 bbox"旧范式上持续打补丁（v19.8~v19.12 的补丁循环）。结论：水从架构层涌入，补丁无效。

### 3.2 照片侧灰化收敛（v19.19 决策）⭐⭐

- **最优**：照片侧（实物打标文字）**只**灰化两类 100% 确定的非标识文本：纯尺寸数字（`_is_dimension`）+ 纯 OCR 垃圾（`_is_cjk_garbage`）。
- **CAD 规则（`_is_cad_annotation` 全量）退回块侧**：块图来自 CAD 图纸，CAD 规则适用；照片来自实物打标，不应套用。
- 效果：恢复 96 个被误灰的打标文字，零退化。

### 3.3 OCR 工具链选型（已定）⭐⭐

- **RapidOCR** = 文字主引擎（唯一稳定达标）。
- **Tesseract** = 灾难兜底（冷启动 fallback 致"忽好忽坏"，故仅留灾难分支）。
- **zxing-cpp** = 二维码/条码主解码器（纯 pip 无 DLL，优于 pyzbar）。
- **PP-DocLayoutV3** = 切图主模型；**OpenCV 轮廓**补充线框视图漏切。
- **结论**：不能完全统一成 PaddleOCR——QR 解码不在其能力内。收敛方向：删 pyzbar、Tesseract 降灾难兜底。

### 3.4 LCD 屏显物理灰化（v2 三重闸）⭐⭐⭐

**最优**：用**物理外观**而非"文本内容"区分 LCD 屏与印刷打标——LCD=浅色数字+近黑底板，印刷暗标签近黑占比仅 0.06–0.12，真 LCD 面板 0.36–0.40（3x 分离）。
三重闸（保守拒认）：① 内容过滤 LCD 形态（数字/符号≥0.8、字母≤0.15、无中文、长度≥2）；② 物理校验 文本外扩6px 近黑像素占比≥0.30；③ 几何面板 膨胀掩膜后质心落"大宽面板"连通域（面积≥2500 且 宽高比≥1.5）。
标定：面板面积误报≤1080 vs 真屏显≥13085（12x 余量）。

### 3.5 屏显图标豁免（B 方案，2026-08-14）⭐⭐

- **决策**：用户规则"屏显内容不标示" → 屏显图标**不画红框也不画灰框**。
- **实现**：`_detect_display_regions` 返回 3 元组 `(regions, disp_keys, panels)`；新增 `_display_icon_indices(icons, panels)`（图标中心落入面板或面积>50%在面板内 → 屏显图标）；`run()` 与 `run_on_photo` 在 `_compare_icons` 前剔除。
- **护栏**：仅 did112 blk1 命中（99 块面板闸校准）；屏灭照片 `_photo_panels=[]` 不误伤真实图标；validate 零回归。
- **复用原则**：不重写 `_compare_icons` 主体，只在其前加过滤——符合"只改必要部分"。

### 3.6 部署与进程架构（关键运维契约）⭐⭐⭐

- **SCG_Platform 部署 C# 改动**：`Stop-ScheduledTask SCG_Platform`（杀看门狗+子进程）→ `dotnet build -c Debug`（.NET 8.0.422 SDK 在 `C:\Program Files\dotnet\dotnet.exe`，不在 PATH）→ `Start-ScheduledTask SCG_Platform`。**直接杀 Platform.exe 会被看门狗秒级重启**。
- **Python 改动即时生效**：C# 每次请求 spawn 子进程重读 `.py`，无需重建。
- **外网穿透**：natapp 免费版风险（域名不定时更换 / 1G/天 / 1Mbps）；长期建议 VIP_1(¥9/月) 或 Cloudflare named tunnel。

### 3.7 测试与护栏方法论（铁律）⭐⭐⭐

- **V-1 端到端 subprocess 验证**：禁 `import run()`，必须真实 HTTP 上传复现（本环境已多次用 `curl POST /api/drawings/diff-photo` 拿铁证）。
- **V-2 逐项枚举 + V-3 坐标级优先视觉**：用 OpenCV 量化红框坐标，与屏显真实位置比对。
- **V-4 生产路径确认**：改动须在生产环境真实跑通。
- **基线护栏**：`validate.py` 锁 `R=28 Y=20 G=588 Gray=664`（G_TOL/GRAY_TOL=25） + `real_match_regression.py` 全量动态 + `fleet_sweep.py` 静态。每次加/退白名单须仅目标块变化、其余零负向。
- **生产数据红线**：Excel 365 in-cell image 形态；图片归属权威 = WPS ClientAnchor `dy1`（xlrd 0-based 行号）。**写入测试必须用临时 ROOT 副本，绝不直接对生产路径写**（曾因 `wb.save(SRC+'.tmp')` 直接覆盖生产丢失 32行/20图）。

## 5. 已知限制与风险清单

### 5.1 功能性限制

1. **最小按钮标签 OCR 漏读（最大遗留）**：`ocr_photo_tiled(grid=(1,1), max_dim_per_tile=800)` 把整张照片压到 ≤800px 才检测；设备占比小 + 标签本身最小时，最小标签经下采样掉出 RapidOCR 可靠阈值（~10px）。当前导致 blk1 残余 1 红框（`长按取消`）。**修复方向**：
   - **A**：`max_dim_per_tile` 800 → 1280/1600（简单但慢）
   - **B**：`grid=(2,2)` 或自适应，每 tile 单独缩到 800（局部小字相对放大；需回归，因 grid=(1,1) 是历史提速选择）
   - **C**：仅对 ROI 内小字做"局部 upscale 再 OCR"二次补救（最小改动）
   - *护栏*：改动 `photo_registration.py:127`，属 H5 照片侧 OCR，**不影响** validate.py 文本基线（R/Y/G/Gray 来自 `run()` 块 OCR，路径独立），但须真实照片回归。

2. **跨块溢出未根治（Phase 2 待办）**：照片 ROI 位置感知已部分缓解（v19.19 收敛灰化），但"字段感知 ROI 匹配范式"的 **Phase 2（标签牌检测裁剪）/ Phase 3（字段语义匹配）/ Phase 4（字段级度量）** 尚未完成。当前靠启发式补丁维持。

3. **缺陷履历模块暂停**：`defecthistory` 2026-08-06 起暂停归档，未恢复。

4. **B 方案 / 照片直接标示 working tree 未提交**：`feature/photo-roi-marking` 分支的 C# 改动与本轮 Python 改动均未 git 提交（环境无 .git 管理，靠文件系统备份）。建议建立版本基线。

### 5.2 架构 / 运维风险

5. **natapp 免费版不稳定**：域名可能不定时更换、1G/天流量、1Mbps 带宽。影响外网 H5 访问稳定性。

6. **seg_root 契约脆弱性**：C# 与 Python 对 `seg_root` 语义（base vs per-drawing）必须严格一致，否则块参考图双嵌缺失 → 静默误标。已修但属"契约即契约"，后续改 `MarkDifferencesOnPhotoCore` 调用须复核。

7. **validate.py 护栏盲区**：`validate.py` 仅统计文本区（`redRegions`/`grayRegions`），**不含 `iconMissingRegions`**。图标比对改动天然不触发回归门禁——既是护栏精简也是盲区，图标类改动须额外人工全量核验。

8. **冷启动竞态**：重启后头几次 ocr_worker 未就绪 → fallback Tesseract（残破），就绪后恢复 RapidOCR。属已知瞬时现象。

9. **生产数据写入高危**：Excel in-cell image 形态 + `dy1` 归属权威，任何写操作须用临时副本。safe-delete 安全层 fail-closed（沙箱回收站不可用 → 拒绝一切删除）。

### 5.3 环境 / 工具限制

10. **C# 改动需 SDK 重建**：本机有 .NET 8.0.422 SDK（不在 PATH，需绝对路径）。Python 改动即时生效。
11. **safe-delete 路径翻译 bug**：把 `E:` 转成 `\e\`，绝对路径删除也 fail-closed（删 .pyc 缓存可忽略）。
