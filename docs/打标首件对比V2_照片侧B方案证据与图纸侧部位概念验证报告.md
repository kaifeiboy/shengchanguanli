## 一、照片侧：一次分块 OCR 能否兜住底（用户要求"确实证据"）

### 实验设计
同引擎（observe.text 同一 RapidOCR 封装），唯一变量 = 输入给 OCR 的区域与尺度：

| 模式 | 内容 | 角色 |
|---|---|---|
| m1 | 整图 warp 后缩 1280 一次 OCR | **现状**（observe 盲检） |
| m2 | 分块 2×3、每块缩 ≤800、overlap 0.25 | **B 方案**（继承 V1 tiling） |
| m3 | 分块 3×4 | 更细 |
| m4 | 分块 4×6 | **内容上界**（局部放大率 ≥ 任何定点裁剪） |

坐标统一回基到 warped 图并归一化；跨块重叠去重（IoU≥0.5）；丢失/新增用**内容覆盖度**判定（互为子串 / 公共子串≥0.6 / 多条拼合≥0.8，避免把"OCR 重切分"误判成丢失）。

### 结果（12 张真实照片，均匀抽样自 drawingsv2_photos/202609）

| 对比 | 丢失 | 新增 | 结论 |
|---|---|---|---|
| 现状 m1 → B方案 m2 | **仅 1 条 2 字符碎片 `AB`** | **12 条真实内容**（`LOW_VOLTAGE`、`MAC地址由贴纸更改为激`、`位置尺寸`、`单位/比例/校对` 等） | 分块显著提升召回、几乎零损失 |
| B方案 m2 → 上界 m4 | 14 条，**全部为标题栏字段**（标记/签名/版本/其它，来自图纸翻拍照片）与密集丝印小字的 OCR 乱码变体 | 3 条同类乱码变体 | **打标内容层面 m2 已达上界** |
| m3 vs m4 | 3 条碎片（743/WQ/mm） | — | 更细分块无实质增益 |

平均纯 OCR 耗时：m1 = 4.6s，m2 = 12.5s，m3 = 17.8s（m4 最长 65s/张）。

### 裁决
1. **分块一次 OCR 兜得住底**：打标内容覆盖已等于 4×6 上界；定点裁剪放大（二次 OCR）的全部增益空间已被分块吃掉 —— **支持取消 verify 定点二次 OCR**（代码落地后仍须跑 42 例基线回归做最终确认，预期无假红/假黄回归）。
2. 3×4 无增益且更慢 → **定 2×3**。
3. 代价 +8s/张（先准后快，接受）；后续提速路径：自适应分块（1×1 快扫→按需补细分）、observe/verify 合并进程、常驻进程池。

## 二、图纸侧："部位=正视图" 概念验证 —— **当前 V2Block 不成立**

### 视觉证据（3 份渲染框图，`_p4_blocks_view/p{72,66,63}_page0.png`）
- **p72（HYXC-VH02）**：b1/b3 是「二维码格式说明卡」（非正视图）；b4 模具编号注记；左上正视/侧视图线稿上的打标文字**无任何块覆盖**。
- **p66（YCWA15NCBQ）**：顶部打标行「YCWA15NCBQ 服务热线：400-620-6807 NFC无线控制」**完全未被提取**；b0 是格式说明卡；b3~b6 是尺寸标注。
- **p63（YCWA15NCWQ）**：A作业/B作业正视图内的打标内容、右下「上盖底部二维码标签激光打标格式」卡**均无块覆盖**。

### 根因链（profile 66 代码级复现）
1. 文本层含 `YCWA15NCBQ效果` span，但渲染 crop 确认它是**标题栏里的图纸标题**（norm y=0.864）→ 被 titlebar 过滤（此过滤本身正确）；
2. 顶部真实可见的打标行是**转曲文字**：`服务热线`/`400-620-6807`/`NFC` 均不在文本层 → text_layer 提取路径天然丢失；
3. 真实打标内容与格式说明卡、注记、尺寸标注在空间上被同等聚类 → 块语义混杂。

### 普遍性审计（21 份全量，`_p4_layer_audit.log`）
- **11/21 份文本层缺失关键打标内容**：9 份缺型号（OCR 可检出、文本层无，如 `CMIIT ID; 2022AP13135`），2 份缺服务热线/400（profile 63/66）；
- 所有 A/B 份：渲染 OCR 字符数 ≥ 文本层字符数（平均多 ~60 字）；C 类 2 份文本层 0 字、OCR 正常（164/177 字）。

### 结构性事实：同图纸多块内容高度重复
p72 的 b0/b1/b2/b3 都含 `制造编码/日期代码/B280001` —— 多个正视图打标格式相同 → **纯内容命中必然歧义，部位定位必须内容+几何联合**。

### 结论
**A 类（栅格化再矢量化）图纸的文本层既不完整也不可信（部分转曲 + 重建 span 错位）。以 text_layer 为主的 V2Block 提取路径有系统性缺陷；"块"也确实不等于"部位（正视图）"。**

### 图纸侧重构方向（待拍板后实施）
1. **内容来源改为渲染 200DPI + RapidOCR 为主**（21 份统一走视觉路径，与照片 OCR 同源），文本层仅作坐标精化补充；
2. **部位重新定义**：以「打标内容簇 + 其所在视图区域」聚类（更大间距 + 尺寸/注记过滤前置），产出"部位级"条目；每份图纸的部位数与正视图数人工核对 3 份以上再全量；
3. 落库结构与 BlockMatcher 的"部位命中"接口同步调整（该接口尚未进生产链路，改动不波及现有 marks/比对）。

## 三、建议的执行顺序
1. **照片侧落地 B 方案**（已有证据）：observe 改 2×3 分块一次 OCR → verify 取消定点二次 OCR → 42 例基线回归 + 真实端点交叉验证；
2. **图纸侧重构原型**：渲染 OCR + 部位聚类跑 3 份样本渲染框图 → 视觉核对"块=正视图"后再全量落库。
