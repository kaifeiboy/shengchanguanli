# 打标首件对比 V2 —— 图纸侧「部位提取 + 打标内容抽取」方案（定稿 · 待审核）

> 本文档仅定稿 **图纸侧（模块②部位区分逻辑 + 模块④在图纸侧的输入 + 坐标映射基础）**。
> 照片侧预处理、照片↔图块配对 UI、H5 展示为后续阶段，不在本文档范围（见 §12）。
> 本文档所有结论均来自对真实 21 份图纸的只读实证（见 §3），未改动任何模块代码。

---

## 1. 目的与范围

原设计（桌面稿《矢量PDF图纸信息提取与激光打标匹配项目方案.md》）要求：图纸按「产品视图 / 打标区域」切分为**图块（逻辑上的产品单一部位）**，块内抽取应打标对象（型号、服务热线、二维码等），与照片 OCR 内容做 1:1 命中比对。

现实现偏离：图纸侧**未做图块提取**，改用「离 mark 最近的视图词文本块」猜部位 → `MarkView` 仅 5 枚举 → p58 约克10寸屏 4 个 mark 全 `Unspecified`，下游匹配/标示全部失焦。

本文档定稿图纸侧提取方案，覆盖全部三类图纸，使每一份图纸都能产出：
- **部位图块列表**（每个图块 = 一个产品单一部位，带页面 `norm_bbox`）；
- **每个图块内的「真实打标候选内容」**（文本 + 图像对象如 QR/logo），供模块③/④消费。

## 2. 设计目标与硬约束

| 约束 | 说明 |
|---|---|
| **G1 三类全覆盖** | A 栅格化(17) / B 原生矢量(2) / C 文字转曲(2) 全部须产出部位图块 + 打标内容 |
| **G2 源文件夹只读** | `E:\生产打标效果图` **仅读取，绝不写回**。派生产物只落 `data/drawingsv2.db` 或独立派生目录 |
| **G3 提取在建档案期** | 图块提取为**一次性**操作（建/更新档案时），比对期（`/api/drawingsv2/compare/upload`）只读库，不重跑提取 |
| **G4 逻辑图块非物理切块** | 图块是「文本 span + 图像对象按空间聚类」派生的逻辑区域，不是 V1 物理裁剪 |
| **G5 严格 1:1 预备** | 每个图块代表一个部位，供照片 OCR 内容做「图块↔照片」命中匹配（配对在模块③） |
| **G6 噪声须舍弃** | 标题栏、会签栏、技术要求/说明块不得进入「打标候选」 |

## 3. 实证依据（真实 21 份，只读 POC）

**3.1 分型（直连 `E:\生产打标效果图`，非 DB 子集）**

| 亚型 | 份数 | 特征 | 提取路线 |
|---|---|---|---|

**3.2 POC 结论（`_poc_block_extract.py` / `_poc_block_extract2.py`，21 份全跑）**

- ✅ **几何聚类有效**：A+B 共 19 份直接聚出 3~11 个部位块；图像对象（QR/logo）与标线数字正确落入块。
- ✅ **真实打标内容捕获有效**：产品型号/生产流水号/供应商代码/`BFF0001`/`QHRNV`/服务热线/`DC15-24V`/`N`/`L`/`IN OUT RS485`/`SD RESET USB` 均正确隔离进部位块。
- ⚠️ **噪声舍弃缺口（已定位，§5.4 解决）**：补全 GB 标题栏词表后，**标题栏整列（更改单号/处数/图纸编号/设计者名/日期/√）、会签栏部门名、技术要求块（整句中文说明）仍漏进打标候选**。固定词表不够，需区域级/模式级过滤。
- ✅ **C 类 vision_fallback 可行**：渲染 200DPI + RapidOCR 恢复 31 条文本，含 `禁止接入强电`/`GND`/`IN`/`OUT`/尺寸数字 → 文字可恢复（见 §6.5）。

## 4. 总体架构（建档案期流水线）

```
输入 PDF（只读 E:\生产打标效果图）
   │
   ├─ 分型判定 ──────────────────────────────┐
   │   words>=20 且无位图 → B 原生矢量        │
   │   words>=20 且有位图 → A 栅格化         │
   │   words<20 且无位图 → C 文字转曲        │
   │                                          │
   ├─ A/B：page.get_text("dict") + get_image_info() ── 取 span bbox + 图像 rect
   │                                          │
   └─ C：page.get_pixmap(dpi=200) → RapidOCR ── 取 OCR 文本 + bbox
                                              │
                      统一 ↓（节点 = bbox + 文本/图像）
       空间聚类（gap 并查集，阈值≈38pt）
                       │
       块内分类（dim / noise / mark / img）
                       │
       噪声三步过滤（§5.4）
                       │
       落库：V2Block + V2BlockMarkCandidate（norm_bbox 约定 [x,y,w,h]∈[0,1]）
                       │
   比对期只读库（/api/drawingsv2/compare/upload 消费图块列表）
```

## 5. A/B 类处理（文本层 span + 图像对象空间聚类）

### 5.1 节点构造
- 文本节点：遍历 `page.get_text("dict")` 的 block→line→span，取非空 span 的 `bbox` 与文本。
- 图像节点：`page.get_image_info()` 取每个内嵌图像 `bbox`（QR/logo）。

### 5.2 空间聚类算法（gap 并查集）
- 两节点连接条件：存在一轴重叠且另一轴间隙 ≤ `THR`（建议 38pt，需在回归中确认），或两轴间隙均 ≤ `THR`。
- 连通分量 = 一个逻辑图块。
- 阈值扫描实测：20/30/38/50 对多数图纸稳定；38 在「不跨块、不碎块」间最稳，最终以 §9 验收回归定稿。

### 5.3 块内分类
对图块内每个文本 span 判类：
- `dim`：纯数字/小数/带 ± 公差（标线的数字部分，如 `86±0.2`/`39.4±0.4`/`150.3`）。
- `noise`：标题栏/会签栏/说明性词汇命中（见 §5.4 词表 + 区域规则）。
- `mark`：其余 → **真实打标候选**（型号/服务热线/二维码内容/端子标识等）。
- `img`：图像节点 → 打标候选（QR/logo）。

**图块 = 产品部位** 的判定：`n_mark>0` 或 `n_img>0`（含真实打标内容或图像对象者即为有效部位块）。

### 5.4 噪声三步过滤（解决 §3.2 缺口，纯规则、低风险）
1. **标题栏整列**：块跨度 `高度 > 80%×页高` 且 `宽度 < 25%×页宽` 且贴页缘（左/右）→ 整块丢弃（POC 中 p59 标题栏 x13~189、满高 y20~846 即此型）。
2. **技术要求/说明块**：块内含「技术要求」头，且块内多为整句中文、字母数字打标 token 占比低 → 丢弃。
3. **会签栏部门名**：`技术部/电子部/品质工程部/货仓部/采购部/市场部/文控中心/发放部门/生产部/物控部` 等 → 丢弃（去空格匹配，因 PyMuPDF 偶在字间插空格）。

> 这三步在 POC 后仍漏的「更改单号/处数/图纸编号/设计者名/日期/√勾」随标题栏整列规则（步骤1）一并丢弃；技术要求整句随步骤2丢弃。

### 5.5 「带标线部位」判定（辅助信号，非唯一依据）
部位块内 `n_dim ≥ N`（建议 N=1，待回归）即「带标线」——用于区分「纯标识区」与「带尺寸标注区」，供模块③展示/排序参考。**真实部位判定以 §5.3 的 `mark`/`img` 为准**，标线数字仅作辅助。

## 6. C 类处理（文字转曲 → vision_fallback）

### 6.1 触发条件
分型 = C（`words<20` 且无位图），或 A/B 聚类后某区域文本层为空但仍疑似含打标 → 降级渲染。

### 6.2 渲染 + OCR
- `page.get_pixmap(dpi=200)` → PNG（落派生目录，不回写源）。
- RapidOCR（项目 default venv 已装）识别，**取文本 + 其页面 bbox**。

### 6.3 OCR bbox 走同一流水线
OCR 结果（文本 + bbox）作为节点，喂入 §5.2 聚类 + §5.3 分类 + §5.4 噪声过滤——与 A/B 完全对称。

### 6.4 QR / logo（C 类为像素）
渲染图上调用 QR 解码（复用既有 `QrDecodeService` / 视觉步骤）提取二维码内容，作为图像节点纳入图块。

### 6.5 实证（已验证可行性）
日立/海信各渲染 + RapidOCR 恢复 31 条文本，含 `禁止接入强电`/`GND`/`IN`/`OUT`/尺寸数字 `2.3`/`1.9`/`4.3`/`150` → 文字与尺寸可恢复，C 类部位提取有解。
> 注：C 类「OCR bbox 聚类成图块」为设计对称步骤，文本恢复已实证，聚类本身在实施期用同 2 份回归确认。

## 7. 数据模型（落库，比对期只读）

新增表（或扩展 `v2_drawing_profiles`），均在 `data/drawingsv2.db`：

- **V2Block**：`id, profile_id, part_index, norm_bbox[x,y,w,h]∈[0,1], n_mark, n_img, n_dim, has_dim, source('text_layer'|'vision_fallback')`
- **V2BlockMarkCandidate**：`id, block_id, kind('text'|'img'|'qr'), raw_text, norm_bbox, is_dim`

> `norm_bbox` 沿用现有 `[0,1]` 约定，与照片侧坐标同一尺度，供模块③配准。

## 12. 坐标映射与标示定位（补充，对应原设计坐标要求）

> 本节回答「逻辑图块里的打标候选如何在匹配标示中落到正确位置」。原设计对此有明确要求，现代码也已有坐标基座，图纸侧只需保证每个候选带坐标流入。

### 12.1 原设计的要求（桌面稿，逐条）
- **对象双坐标**（§对象保存段）：每个打标对象必须保存「**图纸原始坐标 + 归一化坐标**」，方便不同尺寸/渲染比例下做位置映射。
- **图块带基准**（§图块段）：图块保存「**基准点、比例、方向**」+「**打标对象透明层**」；透明层用于在图纸块上绘匹配结果，基准点供照片↔图块配准。
- **照片侧带坐标**（§照片段）：照片识别须保存「字符坐标 + 置信度」，不能只存整段字符串；QR/图标只比存在性 + 位置。
- **标示定位规则**（§标示段）：绿=对象找到且位置正确；红=缺失/错误/**明确位置错误**；黄=位置明显偏移 / 一侧存在一侧不存在 / 质量不足；**图纸块显示「要求位置」，照片显示「实际位置」，同一对象状态**。
- **配准基准**（§照片质量段）：平面件用边框/孔位/面板轮廓/QR 作基准点；基准不足→降匹配置信度 + 人工复核。

### 12.2 现代码已有坐标基座（无需从零造）
`MarkVerifier.cs` 已实现完整坐标链：`mark.NormBbox`（页面坐标，硬规则**不参与** RebaseToView/仿射，作 `DrawingBbox` 图纸回显）、`RebaseToView`（页面→视图/照片坐标）、`ViewBboxOf`（视图锚点并集）、`ApplyAffineRegistration` + `EstimateAnchorTransform`（P3 QR 锚点）+ `EstimateConsistentOffset`（P27）+ `PositionOk`（位置容差）；照片侧 `obs.Texts[].NormBbox` / `QrNormBbox` 带坐标。**结论：坐标映射骨架已存在，图纸侧的唯一职责是保证每个候选携带 `norm_bbox` 流入该基座。**

### 12.3 图纸侧须落库的坐标字段
- `V2BlockMarkCandidate.norm_bbox`：`[x,y,w,h]∈[0,1]`，**图纸页面坐标**（A/B 来自 span bbox / 图像 rect；C 来自 OCR bbox 归一化）= 原设计「归一化坐标」。
- `V2BlockMarkCandidate.orig_pt`（可选）：原始页面点坐标(pt)，对应原设计「图纸原始坐标」，保真用。
- `V2Block.anchor_norm`：图块基准点（优先块内 QR 中心，否则首个 mark 中心），供模块③ `ApplyAffineRegistration` 配准；`V2Block.norm_bbox`（块外接矩形）供视图级 `RebaseToView`。

### 12.4 三类坐标精度与可行性
| 类 | 坐标来源 | 精度 | 可行性 |
|---|---|---|---|
| A 栅格化 | 文本层 span bbox（与位图同页，原生） | 高（亚像素级页面坐标） | ✅ 图纸回显/配准均精确 |
| B 原生矢量 | span bbox（真矢量） | 高 | ✅ 同上 |
| C 文字转曲 | RapidOCR bbox @200DPI 渲染 | 中（±几 px → norm ±0.002~0.005） | ✅ 标示定位够用；位置偏移判定容差略放宽，或渲染 300DPI；基准不足按原设计降置信 + 人工复核 |

### 12.5 标示定位闭环（图纸侧给模块③/④的契约）
- **图纸块回显**：用候选**未变换**的 `NormBbox`（页面坐标）在透明层/局部图上绘「要求位置」（原设计§标示段）。
- **照片画布**：模块③把照片 obs 坐标经 `RebaseToView` + 配准映射到视图坐标，绘「实际位置」。
- **位置判定**：`PositionOk(expected=候选NormBbox, observed=照片命中bbox, offset, tol)` → 绿 / 红（明确位置错误）/ 黄（位置明显偏移）。
- **缺坐标兜底**：C 类某候选 OCR 未返 bbox → 退回块中心 + `needsReview`，**不硬猜位置**（避免假红/假绿）。

### 12.6 风险
- C 类坐标精度低于 A/B，位置偏移类（黄）判定阈值需**按类差异化**（A/B 紧、C 宽）。
- 透明层/局部图渲染属 H5 展示层（§13 范围外），但**坐标基准备自本节**。
- 图块基准点若块内无 QR/稳定结构，退化为块中心 → 配准精度降，须人工复核（原设计§照片质量段）。
