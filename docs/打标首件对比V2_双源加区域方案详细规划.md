### 2.2 过覆盖的正确判据（我先前用错了）

我先按"单区域面积 > 0.20"筛过覆盖 → **结果为 0，判据无效**。
P72 那个框住两部位的框 `area=0.112`，面积不大但**宽 0.484、长宽比 2.1**。
→ **过覆盖不表现为面积大，而表现为"框内包含多个空间分离的内容簇"**。必须用内容簇/投影分割校验，不能靠面积阈值。

### 2.3 V1 为何在此卡很久（关键发现）

- V1 的 `pp_doclayout_onnx.py` **已写过**过覆盖拆分函数 `_try_split_block()` + `_find_boundary()`（投影找分割带，第 370/398 行）。
- 但 grep 全模块：**`_try_split_block` 没有任何调用点** —— 是**死代码，从未启用**。
- `detect()` 主流程只做"舍弃"，不做"分割"，所以过覆盖大框一旦过了 `MIN_SCORE` 就保留下来。
- P72 实证：`[0.116,0.516,0.484,0.231]` score=0.37（> MIN_SCORE 0.34）、`rescued=False` → **过覆盖机制没剔除它**。

### 2.4 我先前"QR 规则误杀"的假设——更正

我怀疑 V1 的 `_is_qr_code_dominant`（QR 主导→舍弃）会误杀真实打标 QR。实测（p66/p72）**该假设不成立**：
被 QR 规则判定的 6 个块，全是**独立小 QR 图**（area 0.002~0.024，位于右侧"二维码格式说明卡"内），本就该舍弃；真实打标 QR 在正视图内只占小部分，不会触发"主导"。
→ 这条规则**可作为"区域外小图过滤"保留，但不能用于部位判定**。

## §4 「双源 + 区域」方案设计

### 4.0 总体原则

**区域（正视图）是唯一权威边界；内容从区域内取；边界错了后面全错。**
因此本方案把**区域界定的可靠性**放在第一位，内容提取第二位。

### 4.1 阶段 P1 — 区域界定（通用，不依赖历史数据）

1. 渲染全页 200DPI → PP-DocLayoutV3 ONNX（只读调用，venv 已有 onnxruntime）
2. 保留 V1 的**几何舍弃规则**（这些是有效的）：
   `MIN_SCORE=0.60`、面积占比 `0.003~0.40`、长宽比 `≤10`、子检测冗余去重、过覆盖父框舍弃
3. **不继承**语义舍弃：`_lacks_dimension_text`（缺尺寸文字→舍弃）、`_is_qr_code_dominant`（降级为区域外小图过滤）

### 4.2 阶段 P2 — 过覆盖拆分（V1 缺失的关键一环）

对每个保留区域，做**内容簇校验**：
- 渲染区域内裁剪 → 水平/垂直投影找**空白分割带**（复用 V1 的 `_find_boundary` 思路）
- 若存在贯穿性空白带且两侧各有独立内容簇 → **拆分为两个区域**
- 若无法可靠拆分 → **标记 `needsReview`**，转人工（不硬猜）

判据不靠面积阈值（§2.2 已证伪），靠**投影空白带 + 内容簇分离**。

### 4.3 阶段 P3 — 欠覆盖检测与兜底

- 3 份仅检 2 块（p54/p56/p57）需核查：是图纸本就简单，还是漏检
- 兜底：**区域内内容量异常**（如某区域内容远多于其它、或页面有大片视图区未被任何区域覆盖）→ 标记 `needsReview`
- 另可辅以**矢量图形轮廓**（`page.get_drawings()`）做交叉验证（A 类图纸线条被切碎，仅作参考不依赖）

### 4.4 阶段 P4 — 双源内容提取（区域内）

```
区域内内容 = text_layer 命中（优先，零误识）
           ∪ 渲染 OCR 补齐（仅当区域内 text_layer 内容量不足，或该图纸属 C 类转曲）
```

- **text_layer 为主** → 绝大多数图纸 0.3s 完成，零误识
- **渲染补齐按需局部化**：只对内容不足的区域局部渲染高 DPI（非全页）→ 范围小、噪声少、比全页快一个量级
- C 类（日立/海信，文本层 0 字）→ 直接走渲染路径（现状 `vision_fallback` 已覆盖）

### 4.5 阶段 P5 — 部位内容集构建

```
部位内容集 = { 区域内所有 text/image 候选 } − { is_dim 尺寸标注 }
```

- QR/图像对象（`kind=image`）在区域内 → **计入**（你对 P66 b1 的更正）
- 尺寸标线数字 → **排除**（你的明确要求）
- 区域外一切 → 不进集（自动排除格式说明卡、模具表、指示性文字、标题栏）

### 4.6 阶段 P6 — 落库与降级

- `v2_drawing_blocks` 增加 `region_bbox` / `region_index` / `needs_review` 字段
- 仍是**逻辑块，不切图**
- 任何阶段不确定 → 标 `needsReview` 转人工，**不硬猜产出假数据**

## §5 可靠性评估（诚实）

### 已验证可靠的
- PP-DocLayout **21/21 无完全失败**，区域粒度接近正视图（p66/p72 人工核对 11/11 为真实视图）
- 几何舍弃规则（分数/面积/长宽比/冗余去重）有效
- 双源互补确凿（11/21 文本层缺内容；渲染能补但慢 150 倍）

### 仍有风险的（必须处理，否则不可靠）
| 风险 | 量化 | 处置 |
|---|---|---|
| **过覆盖**（一个框多部位） | **10/21 份**，15 个区域 | P2 拆分校验；不可靠则 `needsReview` |
| **欠覆盖** | 3 份仅 2 块 | P3 检测 + 人工确认 |
| **悬空打标行**（p66「上盖打标内容」在框外） | 至少 1 份确认 | 需"标题关联 + 邻近"归属规则，**逐份验证** |
| **无真值** | 0 条照片↔部位标注 | 无法量化验收（见 §6） |

### 无法回避的硬阻塞
1. **零真值配对** —— 所有"准确"只能靠肉眼，无法出指标。**请你给 3~5 张已知部位归属的照片**。
2. **"逻辑块不切图能否准确匹配"** —— 无法离线证明，必须端到端真值验证。
